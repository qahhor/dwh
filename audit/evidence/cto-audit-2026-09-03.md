## Критические точечные проверки

- Бизнес-лимит файла 50 МБ задан в
  `apps/server/src/main/java/com/greenwhite/dwh/instance/mf/service/MfFileService.java:24-46`.
- В активном `application.yml`, production Compose и
  `apps/web/nginx.conf:1-55` не найдено `spring.servlet.multipart.*` либо
  `client_max_body_size`. Лимит 100M есть только в отдельном
  `deploy/nginx/nginx.prod.conf:14`, который не является web-конфигом
  production Compose. Spring Boot's official
  [`MultipartProperties`](https://docs.spring.io/spring-boot/api/java/org/springframework/boot/servlet/autoconfigure/MultipartProperties.html)
  documents defaults of 1 MB per file and 10 MB per request, both below the
  application contract.
- Upload выполняет storage upload, malware scan, copy и DB insert внутри метода
  `@Transactional`: `MfFileService.java:43-150`; pool ограничен 20 соединениями:
  `apps/server/src/main/resources/application.yml:18`.
- File scanner fail-closed только при `required=true`, а default — false:
  `FileScannerStartupCheck.java:19-36`, `application.yml:107-108`,
  `docker-compose.prod.yml:30`.
- Task и file read endpoints проверяют функциональное право, но в просмотренных
  service-методах нет проверки owner/project/member для конкретного объекта:
  `MsTaskController.java:136-178`, `MsTaskService.java:176-203`,
  `MfFileController.java:75-85`, `MfFileService.java:207-216`. Является ли это
  уязвимостью, зависит от release-требований: `docs/adr/ADR-0013-data-scope.md`
  явно фиксирует текущее поведение «право view видит все задачи» и default
  `ALL`, но отдельную политику чтения файлов в просмотренных документах найти не
  удалось. Threat model при этом заявляет scoped task/file checks.
- Metrics endpoint и custom counters есть, но bundled collector, alert delivery
  и external log aggregation отсутствуют по
  `docs/ops/architecture-overview.md:98-104`.

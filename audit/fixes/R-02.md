# R-02 — Декомпозиция frontend mega-components

## Решение

Не делать big-bang rewrite. Начать с `TasksComponent`: зафиксировать user journeys, затем по одному извлекать toolbar/filter, list, detail, comments/files и editor в presentational components. HTTP/state orchestration оставить за feature facade.

## Затрагиваемые файлы

- `apps/web-instance/src/app/features/tasks/tasks.component.ts`
- `apps/web-instance/src/app/features/iam/users/users.component.ts`
- `apps/web-instance/src/app/features/iam/roles/roles.component.ts`
- `apps/web-instance/src/app/features/settings/settings.component.ts`
- `apps/web-instance/src/app/features/audit/audit.component.ts`
- соответствующие `*.spec.ts`

## Псевдокод

```text
feature container -> facade/state -> API
feature container -> typed presentational inputs/outputs
```

## Валидация

- [ ] Внешние routes и API contracts не меняются.
- [ ] Каждый извлечённый блок имеет focused component test.
- [ ] Playwright journeys остаются зелёными.
- [ ] Нет дублирования design tokens и error handling.
- [ ] Компоненты сокращаются итеративно, без расширения продукта.

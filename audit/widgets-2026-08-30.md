# UI/UX audit — 2026-08-30

## Итог

Проведён сквозной аудит обеих Angular-оболочек: `apps/web-instance` и `apps/web-cp`. Работа была направлена на углубление существующего продукта: исправлены контракты состояний, клавиатурная навигация, доступные имена, семантика, обратная связь, адаптивность и консистентность действий без добавления новых продуктовых сценариев.

На момент завершения аудита известных критических или высокоприоритетных UI-дефектов в проверенном контуре не осталось. Последний найденный в живом браузере дефект — отсутствие `<main>` и заголовка первого уровня на экране входа `web-instance` — исправлен и покрыт регрессионным тестом.

## Исправленные классы несоответствий

| Приоритет | Проблема | Исправление |
| --- | --- | --- |
| P1 | Модальные окна не гарантировали полный клавиатурный цикл | Добавлены начальный фокус, focus trap, Escape, восстановление фокуса и блокировка фоновой прокрутки |
| P1 | Ошибки входа и отправки форм не имели устойчивой доступной обратной связи | Добавлены inline errors, `role="alert"`, `aria-invalid`, `aria-describedby`, loading/disabled states |
| P1 | Часть экранов и действий зависела от клика по неинтерактивному контейнеру | Действия перенесены на нативные кнопки/ссылки, ложные click-targets удалены |
| P2 | Поиски, фильтры, таблицы и группы не всегда имели доступные имена | Добавлены labels, `aria-label`, regions и именованные table containers |
| P2 | Сортировка и раскрытие состояний не были полностью доступны с клавиатуры | Использованы кнопки, `aria-expanded`, связанные regions и альтернативы drag-only управлению |
| P2 | Прогресс отображался только визуально | Добавлены `role="progressbar"` и значения `aria-valuenow/min/max` |
| P2 | Вкладки и панели имели неполный ARIA-контракт | Добавлены `tablist`, `tab`, `tabpanel`, `aria-selected` и связи между ними |
| P2 | Нативные `confirm()` создавали разный UX и слабый контроль фокуса | Все подтверждения заменены единым modal contract |
| P2 | App shell не обеспечивал быстрый переход и явные landmarks | Добавлены skip link, landmarks и доступная mobile navigation |
| P2 | Экран входа `web-instance` начинал иерархию с `h2` и не имел `<main>` | Корневой контейнер заменён на `<main>`, заголовок — на `<h1>`, добавлен тест |
| P3 | Markdown task-list чекбоксы не имели связанной текстовой метки | Чекбоксы обёрнуты в `<label>` в editor и read-only view |
| P3 | Анимации и focus styles были несогласованны | Добавлены глобальный `:focus-visible` и `prefers-reduced-motion` |

## Проверенные состояния

| Состояние | Результат |
| --- | --- |
| Default / hover / focus-visible | Контракт унифицирован; focus ring не подавляется локальными стилями |
| Disabled / loading | Кнопки и формы предотвращают повторное действие и сохраняют понятный статус |
| Validation / API error | Ошибка находится рядом с полем или формой и объявляется assistive technology |
| Empty / no results | Существующие empty states сохранены, фильтры остаются управляемыми |
| Modal open / close | Фокус входит в modal, удерживается внутри, Escape закрывает, фокус возвращается |
| Keyboard-only | Основные действия доступны через нативные controls; drag reorder имеет кнопочные альтернативы |
| Mobile 390×844 | Login-экраны не имеют горизонтального переполнения, controls остаются читаемыми и доступны |
| Desktop 1280×720 | Login-экраны центрированы, форма и hierarchy не ломаются |
| Reduced motion | Анимации и transitions сокращаются на уровне глобального стиля |

## Доказательства

- `web-instance`: 22 test files, 52 tests passed.
- `web-cp`: 3 test files, 5 tests passed.
- Production builds обеих оболочек завершены без ошибок.
- Browser QA: `web-instance` и `web-cp`, desktop и 390×844, без horizontal overflow.
- Browser console: 0 warning/error сообщений на проверенных login-экранах.
- `web-instance` reset modal: dialog count 1 при открытии; начальный фокус на `Закрыть`; Escape закрывает dialog; фокус возвращается на `Забыли пароль?`; computed body overflow — `hidden`.
- Статический повторный скан: отсутствуют native `confirm/alert/prompt`, таблицы без доступного имени, кнопки без `type`, неименованные интерактивные контейнеры в проверенном frontend-контуре.

## Ограничения и остаточный риск

- Полный authenticated end-to-end проход по бизнес-экранам не выполнялся: в задаче не было предоставлено тестовых учётных данных, а сохранённые credentials не использовались. Эти экраны проверены статически, через component tests и production build.
- Реальная интеграция с backend, большие объёмы данных, сетевые таймауты и физические мобильные устройства остаются отдельным интеграционным QA-контуром.
- Автоматизированный axe/WCAG conformance suite в репозитории не настроен; доступность проверялась контрактными тестами, DOM/accessibility snapshot и клавиатурным browser QA.

## Решение

UI/UX hardening для заявленного frontend-контура завершён. Дальнейшее расширение функциональности не требуется; следующая полезная глубина — authenticated E2E на выделенном тестовом tenant с подготовленными ролями и реалистичными наборами данных.

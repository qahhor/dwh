# DevOps and release-readiness audit — 2026-09-03

## Delivery map

Local development and production use Docker Compose. The supported production
topology contains migrations, Spring server, Angular/Nginx web, PostgreSQL,
Typesense and encrypted database backup jobs
(`deploy/compose/docker-compose.prod.yml`). CI verifies backend, frontend,
configuration/docs, clean E2E and security; stable SemVer tags trigger
multi-architecture signed images with SBOM/provenance
(`.github/workflows/ci.yml`, `.github/workflows/release.yml`).

No active Kubernetes, Terraform or applied Hetzner/Cloudflare configuration was
found. Nomad/Vault/Fleet documents are historical and conflict with the current
one-installation/one-organization product if read as active instructions.

## Minimal observability contract

| Signal | Metric / alert | Release threshold |
|---|---|---|
| Availability | external HTTPS synthetic + readiness | page after 2–3 consecutive failures; runbook linked |
| Latency/errors | API p50/p95/p99 and 4xx/5xx rate | alert on SLO burn, not single spikes |
| Saturation | CPU, memory, disk/inodes, JVM heap/GC, DB pool pending/utilization | warn at projected 30-day capacity; page on sustained exhaustion |
| Data paths | PostgreSQL health/locks, R2 errors/latency, Typesense lag | degraded dependency visible and assigned |
| Async | webhook/notification attempts, age and dead letters | dead letter page within 5 min for critical channels |
| Protection | backup age/status, restore age, certificate expiry, scanner health | stale backup/scanner/cert alerts reach owner |

Exact alert thresholds must come from the approved SLO and load baseline; no
production values were available during this audit.

## Deployment/rollback gate

1. Immutable digest and signature verified.
2. Encrypted backup completes before migration; backup failure aborts rollout.
3. Migration job succeeds once; schema version recorded.
4. Web/readiness/synthetic and critical smoke tests pass through Cloudflare.
5. Error/latency/DB-pool/storage signals remain within canary window budget.
6. Failure triggers the documented previous-digest rollback; incompatible
   schema changes require forward-fix/restore decision explicitly tested.

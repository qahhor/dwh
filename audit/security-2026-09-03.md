# Security audit — 2026-09-03

Scope: repository-level review of SmartupCMS at
`df84019886aa47c504e5562253dd1ef842b3d96b`. The baseline is the current
[OWASP Top 10:2025](https://owasp.org/Top10/2025/) and the technical controls
visible in source/configuration. ISO/IEC 27001:2022 is an ISMS requirements
standard; this code audit cannot prove certification or organizational control
effectiveness. Official reference: [ISO/IEC 27001:2022](https://www.iso.org/standard/27001).

## Trust boundaries and protected data

Browser traffic enters one web origin and is proxied to the server. Server-side
boundaries include PostgreSQL, Typesense, object storage, file scanner,
SMTP/SMS/messenger providers and outbound webhook targets. Identity/profile,
authentication telemetry, business content, files, audit events and encrypted
backups can contain personal or confidential data
(`docs/security/threat-model.md:48-59`). Installation-specific legal basis,
retention, support access and accountable owners are not filled in.

## ISO/IEC 27001 readiness view

Code-visible strengths: access controls, audit domain, secure SDLC gates,
dependency lockfiles, signed release design, encrypted DB backups, incident and
security policy documents. Material gaps: asset/risk/control ownership,
Statement of Applicability, supplier/Cloudflare/Hetzner/R2 assessment, access
reviews, key rotation evidence, retention/deletion, vulnerability management
SLA, tested incident response/BCP/restore, monitoring and evidence retention.

**Conclusion:** the repository can support an ISO-aligned implementation, but
“ISO 27001 compliant/certified” is not supported by the inspected evidence.

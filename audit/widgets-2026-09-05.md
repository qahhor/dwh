## 1. Итог и границы проверки

Проверена страница `http://localhost:4200/tasks`: существующая авторизованная
сессия Administrator в Chrome, русский язык, светлая тема; desktop viewport
1536×799 и временный mobile viewport 390×844. Исходники: `main`,
`0802ac899a54477b39d53ba22e872469bcca0611`.

Субъективная инженерная оценка UX — **6/10**: основные действия доступны,
оформление достаточно последовательно, но есть дефекты целостности формы,
полноты выдачи и клавиатурного взаимодействия. Это не пользовательская
метрика, не результат usability research и не сертификат WCAG.

Три системных проблемы:

1. Форма и API расходятся в семантике времени, очистки полей и загрузки участников.
2. Загруженная часть данных выдаётся за полный набор; состояния запросов недостаточно различимы.
3. Внешняя консистентность не подкреплена одинаковым качеством accessibility и контрактных тестов.

## 4. Находки и минимальные исправления

Оценки: XS — до половины инженерного дня; S — примерно 0,5–1,5 дня;
M — примерно 2–4 дня с узкими тестами. Это предварительные оценки, не SLA.
Общие изменения могут закрыть несколько находок одновременно.

### W-01 — P1 / M. Пагинация обрывает доступ к задачам после первых 50

- **Наблюдение:** `loadTasks` запрашивает `limit: 50`. `hasMore` сохраняется, но не используется в шаблоне; вызовы загрузки всегда передают `true`, сбрасывая cursor. Видимая пагинация режет только локальный массив, а `totalItems` равен его длине.
- **Риск:** задача №51 и далее недостижима обычной навигацией; после создания при большой выдаче новая задача может не появиться. При смене фильтра на странице 2+ `currentPage` компонента не сбрасывается, что создаёт пустой срез при непустом результате.
- **Доказательство:** [шаблон пагинации](D:/Claude/dwh/apps/web/src/app/features/tasks/tasks.component.ts:354), [загрузка и срез](D:/Claude/dwh/apps/web/src/app/features/tasks/tasks.component.ts:2504). Backend действительно возвращает keyset: [MsTaskService](D:/Claude/dwh/apps/server/src/main/java/com/greenwhite/dwh/instance/ms/task/service/MsTaskService.java:232). Общий paginator корректирует только собственный input, без уведомления родителя: [calculatePagination](D:/Claude/dwh/apps/web/src/app/shared/ui/ui-pagination.component.ts:283).
- **Минимальное исправление:** выбрать один последовательный cursor-based контракт, реализовать переход к следующей серверной порции, сбрасывать страницу при фильтрах; не называть число загруженных строк общим количеством. Не загружать неограниченно всю БД ради клиентской пагинации. При использовании общего `cursorMode` отдельно проверить его `goToPage`: сейчас он также ограничен вычисленным `totalPages`.
- **Проверка:** изолированный fixture 125 задач; доступны все ID без дублей; фильтр на третьей странице возвращает первую; счётчик честно описывает загруженное/известное количество.

### W-02 — P1 / S. Редактирование может сдвинуть дедлайн на часовой пояс

- **Наблюдение:** ISO timestamp обрезается через `substring(0, 16)`, попадает в `datetime-local`, затем преобразуется `new Date(...).toISOString()`.
- **Риск:** сохранение другого поля незаметно изменит уже установленное время. В UTC+5 это сдвиг на −5 часов для timestamp с `Z`.
- **Доказательство:** [инициализация формы](D:/Claude/dwh/apps/web/src/app/features/tasks/tasks.component.ts:2920), [payload](D:/Claude/dwh/apps/web/src/app/features/tasks/tasks.component.ts:2963); сервер использует `Instant`: [UpdateTaskDto](D:/Claude/dwh/apps/server/src/main/java/com/greenwhite/dwh/instance/ms/task/controller/MsTaskController.java:272).
- **Локальное воспроизведение алгоритма, без API записи:** Node 24.15.0, `TZ=Asia/Tashkent`: `2026-09-05T12:00:00Z` → поле `2026-09-05T12:00` → `2026-09-05T07:00:00.000Z`, `shiftHours=-5`. Это проверка преобразования, не утверждение о выполненном сохранении живой задачи.
- **Минимальное исправление:** единый helper ISO ↔ локальное значение выбранной временной зоны, явная подсказка зоны возле срока, сохранение исходного instant при неизменённом поле.
- **Проверка:** round-trip в UTC, Asia/Tashkent и зоне с DST; изменение только названия не меняет deadline ни на миллисекунду.

### W-03 — P1 / M. Очистка полей формы не совпадает с PATCH-контрактом

- **Наблюдение:** UI предлагает «Без проекта», «Без родителя», очистку ответственного и пустой срок. Payload передаёт `null`, но SQL использует `coalesce(:value, existing_value)`; обновление ответственного вызывается только для non-null.
- **Риск:** после сообщения об успешном сохранении прежние значения возвращаются при открытии карточки.
- **Доказательство:** [payload редактора](D:/Claude/dwh/apps/web/src/app/features/tasks/tasks.component.ts:2955), [SQL update](D:/Claude/dwh/apps/server/src/main/java/com/greenwhite/dwh/instance/ms/task/repository/MsTaskRepository.java:127), [проверка responsibleUserId](D:/Claude/dwh/apps/server/src/main/java/com/greenwhite/dwh/instance/ms/task/controller/MsTaskController.java:225). Сохранение на текущих данных не выполнялось.
- **Минимальное исправление:** различать отсутствующее поле и явный `null`; поддержать очистку в существующем endpoint и транзакционном сервисе. До исправления не показывать очистку как поддерживаемую операцию.
- **Проверка:** задать → очистить → сохранить → повторно открыть для проекта, родителя, ответственного и срока; отсутствие поля в PATCH оставляет значение прежним.

### W-04 — P1 / S. Редактор открывается с вымышленными пустыми участниками при ошибке GET

- **Наблюдение:** error-ветка `openEditModal` подставляет `observerUserIds: []` и всё равно открывает активную форму. Success-ветка берёт основные поля из старого `task`, а не из свежего `res.task`.
- **Риск:** повторное сохранение после временного сбоя может удалить наблюдателей или перезаписать более свежие поля. Снятие ответственного через null сейчас отдельно блокируется дефектом W-03; не утверждаем, что эта ветка снимает его.
- **Доказательство:** [openEditModal](D:/Claude/dwh/apps/web/src/app/features/tasks/tasks.component.ts:2899), [error fallback](D:/Claude/dwh/apps/web/src/app/features/tasks/tasks.component.ts:2926), [setObservers](D:/Claude/dwh/apps/server/src/main/java/com/greenwhite/dwh/instance/ms/task/service/MsTaskService.java:387) удаляет прежние записи перед заполнением нового списка.
- **Минимальное исправление:** при ошибке detail GET показать «Не удалось загрузить задачу / Повторить», запретить сохранение неполной формы; заполнять её свежим `res.task` и `res.members`.
- **Проверка:** mocked 500/403/404 не открывает готовую к сохранению форму и не вызывает PATCH; успешный retry сохраняет наблюдателей.

### W-05 — P1 / M. Loading, error и устаревшие ответы смешиваются с данными

- **Наблюдение:** список не показывает loading row/inline error/retry. Ошибка только снимает `isLoading`; первый неудачный запрос выглядит как пустая выдача. При открытии другой карточки дочерние массивы не очищаются, ответы не привязаны к актуальному taskId.
- **Риск:** пользователь видит старые результаты под новыми фильтрами или прежние комментарии/вложения под заголовком другой задачи. Поздний ответ может заменить уже выбранную карточку.
- **Доказательство:** [empty state](D:/Claude/dwh/apps/web/src/app/features/tasks/tasks.component.ts:340), [loadTasks](D:/Claude/dwh/apps/web/src/app/features/tasks/tasks.component.ts:2504), [openTaskDetails/loadTaskFullDetails](D:/Claude/dwh/apps/web/src/app/features/tasks/tasks.component.ts:2729), [loadComments](D:/Claude/dwh/apps/web/src/app/features/tasks/tasks.component.ts:2779).
- **Уточнение:** общий [ApiService](D:/Claude/dwh/apps/web/src/app/core/services/api.service.ts:107) уже показывает error toast. Проблема не в полном отсутствии сообщения, а в отсутствии устойчивого состояния страницы и корректного восстановления.
- **Минимальное исправление:** раздельные loading/error/data состояния; очистка либо явное маркирование старых данных; `switchMap`/request identity guard; task-scoped черновик комментария. Переиспользовать визуальный паттерн [Audit inline error/retry](D:/Claude/dwh/apps/web/src/app/features/audit/audit.component.ts:221), не вводить новый UI-kit.
- **Проверка:** медленный ответ A после быстрого B не меняет B; закрытая карточка не открывается поздним ответом; 500 → inline error → retry; без ложного «Нет комментариев» до завершения загрузки.

### W-06 — P1 / S. Канбан скрывает фильтр, но продолжает применять его

- **Проверка:** одинаковые фильтры дают одинаковый набор ID в таблице и канбане; завершённая задача доступна без возврата в таблицу.

### W-07 — P1 / S. В комментариях отсутствует имя автора

### W-09 — P1 / S. Текст статуса недостаточно контрастен в светлой теме

- **Наблюдение:** computed style активного select «В работе»: `rgb(234,179,8)` на `rgb(255,255,255)`, размер 11px. Рассчитанный контраст **1,9178:1**.
- **Риск:** статус плохо читается даже при внешне корректной светлой форме.
- **Доказательство:** снимки 01/05; [inline color](D:/Claude/dwh/apps/web/src/app/features/tasks/tasks.component.ts:295), [getStatusColor](D:/Claude/dwh/apps/web/src/app/features/tasks/tasks.component.ts:3104) напрямую использует пользовательский цвет справочника. - **Минимальное исправление:** имя статуса писать контрастным semantic text color, пользовательский цвет сохранять на точке/бордере; либо вычислять проверенный foreground/background pair для каждой темы. Не менять пользовательские цвета в БД ради UI.
- **Проверка:** контраст текста ≥4,5:1 для встроенных и произвольных светлых цветов справочника; отдельно проверить dark theme.

### W-10 — P2 / S. Поиск требует неизвестного пользователю Enter

## 9. Измеримая приёмка и оставшиеся неизвестные

- [ ] Все 125 тестовых задач доступны через навигацию; фильтрация сбрасывает cursor/page.
- [ ] Неизменённый срок не меняется после редактирования в UTC и UTC+5.
- [ ] Очистка nullable fields сохраняется; отсутствие поля в PATCH не стирает значение.
- [ ] Ошибка загрузки не разрешает запись неполной формы и имеет явный retry.
- [ ] Старые ответы не заменяют актуальную задачу, список или комментарии.
- [ ] Таблица и канбан показывают один набор для одинаковых видимых фильтров.
- [ ] Авторы комментариев читаемы; нет голого `@`.
- [ ] Клавиатурное действие открывает один диалог; все поля имеют accessible name.
- [ ] Контраст обычного статусного текста ≥4,5:1 в обеих темах.
- [ ] Доступен поиск пользователей/родителя за пределами первой порции без ослабления прав.
- [ ] На 390px нет общего горизонтального overflow и потерянных CTA.
- [ ] Regression tests выполняются на изолированных fixtures, без загрязнения текущей установки.

Не подтверждены: поведение всех ограниченных ролей, произвольных динамических
полей, реальный round-trip сохранения и очистки в браузере, сетевые сбои,
большой объём данных, все мобильные устройства и полноценная WCAG-совместимость.
Эти пробелы закрываются изолированной проверкой при реализации, а не записью
в реальные задачи в ходе read-only аудита.

В текущих списках видны E2E-наименования и пользовательские справочники
«Чучвара»/«Привет». Это содержимое установки, не ошибка перевода. Их нельзя

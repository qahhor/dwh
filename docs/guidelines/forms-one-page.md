# SmartupCMS: единый стандарт экранов и форм

**Цель:** low-code CMS framework. Одно объявление сущности на сервере задаёт
поля, права и обычный CRUD. Свой экран нужен только для другого способа
работы: дерево, доска, матрица прав или мастер. Прикладные модули отключаемы;
их отсутствие не мешает входу и администрированию. Подробности реализации —
[стандарт форм](forms-ux-standard.md), ADR-0012, ADR-0015 и ADR-0032.
Все экраны и вложенные редакторы перечислены в [реестре форм](forms-catalog.md).

| Область | Единое правило |
|---|---|
| **Каркас** | Один h1 страницы; вложенный экран использует h2 (`headingLevel=2`). `ui-page-header`: название, количество при наличии, действия справа. Один основной призыв к действию. Отступы, шрифт, цвет, высота контролов и состояния — из UI-кита и токенов; светлая и тёмная темы. Действия переносятся на узком экране, заголовок остаётся читаемым. |
| **Навигация** | Один текущий пункт, в том числе на карточке и в компактном меню. Скрытые разделы исключены из Tab; у кнопок есть название раздела. Компактное меню открывается с клавиатуры, стрелки выбирают пункт, Escape возвращает фокус. Высота выпадающего меню учитывает его верхнюю координату и нижний край окна. Мобильное меню удерживает фокус, после перехода фокус — на содержимом. Панель не перекрывает страницу на 768–1023 px. |
| **Список / таблица** | `ui-server-table` + `registryTableConfig` для серверных коллекций; `ui-local-table` для конечного локального набора. Название записи открывает просмотр; сортировка, колонки, фильтры, пагинация и массовые действия используют общие компоненты. Доска, дерево и карточки — дополнительные представления тех же данных, не второй CRUD. Высота длинного серверного списка ограничена: заголовки и полосы прокрутки доступны без прохода через все строки. Диапазон пагинации считается по фактическим строкам, оценка общего количества отмечается отдельно. |
| **Поиск** | Видимое доступное имя, иконка поиска, очистка. Поиск разделов меню учитывает текущие права и переведённые названия; очистка возвращает прежнее раскрытие групп. Серверный поиск данных с задержкой и сбросом курсора; старый ответ не заменяет новый. Отличать «записей ещё нет» от «ничего не найдено»; показывать очистку фильтров. Не выдавать поиск по загруженной странице за поиск по всему справочнику. У свёрнутых дополнительных фильтров виден счётчик, сброс доступен снаружи; полная выгрузка явно названа «без фильтров». |
| **Просмотр** | Название и состояние записи, те же разделы и порядок полей, что при изменении; значения можно копировать. «Изменить» доступно по праву и состоянию записи. История, связи и строки документа — вкладки общего runtime. Отсутствующие значения обозначаются одинаково. |
| **Создание / изменение** | Объявленная сущность — `smt-entity-form`; специальная форма — существующая модель на signals/Signal Forms и `smt-control`. Над полем подпись, ниже подсказка и ошибка; placeholder — пример, не подпись. Сначала идентификация и обязательные поля, затем дополнительные; длинный текст занимает строку. Ширина страницы до 960 px; короткие значения уже длинных названий, многострочные поля на всю строку. При ширине контейнера до 600 px одна колонка. Дополнительные параметры можно сворачивать без потери значений; важный выбор остаётся в сводке. |
| **Сохранение** | Настоящий `<form>`: Enter сохраняет, в многострочном поле переносит строку. `ui-form-actions`: «Отмена», затем «Создать» или «Сохранить». Неверные данные не выключают кнопку: после нажатия показываются ошибки. Во время запроса повторная отправка и закрытие запрещены. Успех закрывает редактор или открывает сохранённую запись. |
| **Ошибки** | После ухода с поля — проверка затронутого поля; после попытки сохранить — всех редактируемых полей. Исправление снимает устаревшую ошибку. Серверные 422 — под полями; неизвестное поле или ≥3 ошибок — общая сводка. Фокус на первом доступном ошибочном контроле, в составном поле — на его активной опции. Блок с ошибкой раскрывается до перехода фокуса. Сеть/403/409/428 сохраняют введённые значения; конфликт предлагает перечитать запись. |
| **Удаление / архив** | Действия различаются текстом. Удаление — отдельная опасная кнопка и общий confirm с названием записи или числом выбранных записей. Запрос идёт с актуальной ревизией, где она предусмотрена. При отказе запись остаётся; показывается причина. Скрывать действие без права. Не добавлять удаление в журнал или системный справочник, где его нет в модели. |
| **Выход** | «Отмена», Escape, крестик, фон и уход со страницы используют один вопрос об отмене изменений; фокус — «Продолжить редактирование». Нетронутая форма закрывается сразу; сохраняемая не закрывается. После диалога фокус возвращается к открывшему элементу. |
| **Состояния и права** | Различать загрузку, пустой результат, ошибку с повтором, отсутствие записи и запрет доступа. Скрытое поле не рисуется и не отправляется; недоступное для изменения значение остаётся читаемым. Решение о доступе всегда принимает сервер. Отключённый модуль недоступен через меню и прямую ссылку. |
| **Доступность и языки** | Доступные имена, связи подсказок и ошибок, Tab/Shift+Tab, видимый фокус, Escape, корректный focus trap. Редактор открывается с фокусом на поле; сложный диалог — на первом доступном контроле содержимого. Крестик доступен с клавиатуры после содержимого. Даты — `dd.MM.yyyy`, время — 24-часовое. Проверять 360 px и 1280 px, обе темы. На узком экране кнопки, вкладки, пагинация и закрытие диалога имеют зону нажатия не меньше 44 px при ширине до 767 px; компактный переключатель сохраняет небольшой индикатор внутри этой зоны. Ширину колонок можно менять клавиатурой; фокус указателем не сдвигает вкладку до завершения нажатия. Все подписи/ошибки/состояния переведены на ru/uz/en. Цвет не является единственным сообщением. |

**Критерий готовности:** инвентаризация включает все маршруты, диалоги,
вложенные редакторы и сущности. У каждого применимы и проверены список,
поиск, просмотр, создание, изменение, удаление/архив и отрицательные
сценарии; неприменимое явно отмечено. Ноль исключений `forms:audit`,
успешные web audits, типизация, unit-тесты, build, E2E и a11y; изменения
серверных контрактов дополнительно проходят серверные проверки. Скриншот
подтверждает внешний вид, но не заменяет проверку поведения и доступа.

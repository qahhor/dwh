# Рецепт: новая форма из Студии через CLI/Flyway

**Основание:** [ADR-0037](../adr/ADR-0037-simple-form-cli-delivery.md), [контракт](../architecture/admin-studio-contract.md), [план](../architecture/admin-studio-plan.md). Рабочий эталон декларации — [simple-form.example.json](../api/simple-form.example.json); генератор проверяется `tools/cms-cli/scripts/smoke.mjs` на отдельной копии репозитория.

## Подготовить форму

1. В «Настройки → Новая форма» администратор с `md.settings.update` задаёт модуль, код справочника, названия ru/uz/en и дополнительные поля. `name` и `code` обязательны и встроены; `modifiedAt` системный. Порядок меняется кнопками. Снятие «В списке» оставляет поле в форме и физической таблице.
2. «Сохранить черновик» выгружает локальный JSON, в том числе незавершённый. Общая история серверных черновиков STU-02 относится к настройке существующего представления и для новых схем не используется. Импорт файла проходит серверную проверку структуры до замены текущего ввода. Незавершённые названия и числовые ограничения сохраняются; импорт не готовит пакет.
3. «Проверить» валидирует декларацию, показывает предпросмотр через общий renderer и готовит пакет с checksum. Любая следующая правка делает пакет устаревшим; необходимо проверить снова. Ошибка проверки не очищает ввод.
4. Скачать актуальный пакет и передать разработчику. Он ещё не является действующей формой и не разрешает автоматический deploy.

## Доставка разработчиком

В отдельной рабочей ветке с сохранёнными исходными изменениями:

```bash
node tools/cms-cli/bin/cms.mjs form apply /path/to/form-package.json --dry-run
node tools/cms-cli/bin/cms.mjs form apply /path/to/form-package.json
```

Сервер и CLI используют общий список запрещённых имён: ключевые слова Java и имена устройств Windows (не проходят Git index) для модуля; ключевые слова PostgreSQL, системные колонки и зарезервированные поля runtime для полей. Незавершённый черновик может содержать такие имена, но пакет подготовить нельзя.

CLI повторно проверяет закрытый JSON, checksum, конфликты кодов/файлов/таблиц, совместимость модуля, длины имён и наличие receipt. Затем создаёт `EntityDefinition`, contract test, таблицу и права отдельными Flyway-миграциями со следующими свободными номерами, manifest, переводы и нужные записи реестров. Общая страница `/e/<module>.<entity>` не требует нового Angular CRUD.

Receipt `docs/declarations/<module>.<entity>.json` входит в исходники. Он различает первый запуск, точный повтор и несовместимую новую схему; контрольные суммы файлов описывают начальную генерацию. Точный повтор ничего не меняет, даже если разработчик дописал Java. Отсутствующий созданный файл не восстанавливается автоматически. Изменённый пакет для той же сущности отклоняется, включая required/type/delete, добавление и скрытие полей. Для развития существующей схемы нужен отдельный инженерный change с анализом данных и зависимостей; редактор этой автоматизации не обещает.

Проверьте diff, переводы и права. Начальные grants ограничены `chief_admin`/`admin`; прочим ролям доступ назначается явно. Скоуп справочника ALL ограничен правами на сущность, не владельцем строки. Затем выполните полный локальный CI по AGENTS.md, включая `scripts/dev/test-cms-cli.ps1`, API contract/types и `EntitySchemaContractTest`. Созданный contract test проходит общие CRUD/ACL/ревизии; дополнительные бизнес-правила требуют собственных тестов.

После утверждения выпуска: резервная копия → штатный шаг `migrate` → приложение с теми же миграциями/объявлением → smoke формы и выдачи прав. Редактор и CLI сами не публикуют изменения.

## Повтор, конфликт и прерывание

- `--dry-run` не пишет исходники. Разные декларации с одинаковым кодом никогда не объединяются молча.
- Генерация блокируется lock-файлом `.local/cms-form-delivery.lock` и сверяет прочитанные исходники перед записью. Синхронная ошибка ввода-вывода вызывает попытку восстановления уже затронутых файлов. Конкурентные ручные изменения должны сохраняться.
- Остановка процесса/питания не является транзакцией файловой системы. После прерывания остановите выпуск: сравните исходники с сохранённой базой Git, manifest и receipt, восстановите только файлы этой генерации, проверьте отсутствие другого процесса. Снимать оставшийся lock можно после этой проверки. Не редактируйте checksum выпущенных миграций для обхода ошибки.
- Если Flyway ещё не выполнялся, откат состоит в возврате проверенных исходников. После применения новой таблицы откат приложения не удаляет её и данные; DROP автоматически не выполняется. Восстановление данных — по штатному backup/restore runbook и отдельному подтверждённому плану.

## Ограничения

CLI-доставка не активирует форму без deploy. Для ограниченного namespace studio доступен отдельный [механизм активации](live-simple-forms.md). Редактор не изменяет схемы существующих форм и не создаёт ссылки, произвольные hooks/SQL/скрипты или общие серверные черновики новых схем. Контрольная сумма защищает от случайного повреждения, не заменяет code review, подпись или разрешение на выпуск. Новые dependencies не нужны.

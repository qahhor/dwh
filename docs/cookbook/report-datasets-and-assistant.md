# STU-06: графики, подготовленный набор данных и помощник

Решение и ограничения: [ADR-0039](../adr/ADR-0039-report-datasets-and-assistant.md). Локальные результаты записываются в [плане §15](../architecture/admin-studio-plan.md); наличие этой инструкции не означает выполненную приёмку.

## Подготовленный набор данных

Первый выбранный владельцем сценарий связывает задачи с проектами: ms.tasks.projects, reference projectId, проекции projectCreatedAt из createdAt и projectModifiedAt из modifiedAt. Это один переход REF N:1; grain — одна задача, count считает задачи. LEFT JOIN не умножает количество. Задача без проекта либо с архивным/недоступным по scope проектом даёт NULL проекции. Отзыв view у целевой сущности закрывает весь источник. Закрытое target-поле исчезает из metadata; сохранённый отчёт, использующий такое поле, недоступен. Выключение модуля «Задачи и проекты» закрывает набор.

Доверенный разработчик объявляет EntityReportDataset как bean; произвольный SQL из браузера не принимается. Корневая сущность и target обязаны иметь модель. До 16 datasets на root. Допускается один REF, 1–16 проекций SELECT/BOOL/DATE/INSTANT. Проекции nullable и несортируемые. Необязательный labelKey задаёт явную подпись проекции из каталогов ru/uz/en; например «Проект: создан», чтобы не путать её с датой самой задачи. Права и тип наследуются от исходного поля. Проверки декларации и текущих прав выполняет EntityReportDatasets. Динамические joins и редактор отношений не входят в эту версию; новый business dataset требует собственного grain и golden результата.

API на существующей сущности:

- GET /api/v1/entities/{code}/report-datasets → items с code/titleKey доступных наборов.
- GET /api/v1/entities/{code}/report-meta?dataset=… → metadata выбранной проекции.
- Optional dataset в direct report, агрегированном экспорте и сохранённом state.
- Панель ссылается на прежний сохранённый report/viewId; расчёт и XLSX используют один разрешённый источник и текущего читателя. Период панели может использовать разрешённую DATE/INSTANT проекцию из канонического dataset отчёта; скрытие этого поля закрывает виджет.

Эталон: откройте отчёт списка задач, выберите «Задачи и проекты», группу projectCreatedAt с шагом день и меру «Количество». Для разреза по приоритетам выберите priority и horizontalBar. Сохранённый отчёт можно добавить в панель и явно связать её период с projectCreatedAt; экспорт считает те же видимые задачи. NULL в дате проекта не превращается в фиктивную дату: если результат содержит такую группу, line показывает точную таблицу с объяснением. Для временного графика можно явно отфильтровать задачи без даты проекта; строковые меры NULL и пропущенные календарные периоды дают разрыв линии.

## Графики

line требует одну DATE/INSTANT группировку с календарным bucket и одну меру. UTC, отрицательные числа допустимы, NULL и отсутствующий период разрывают линию. horizontalBar требует одну категориальную группировку и одну меру, показывает ось нуля. Результаты не пересуммируются. Валютная неоднозначность, усечение, неподдерживаемая размерность или нечисловая мера переводят отображение в точную таблицу с пояснением. Таблица доступна и рядом с графиком; значения не зависят от hover или цвета.

## Помощник черновика

Для доступа нужны оба права studio.forms.assist и md.settings.update, активный studio. Начальный grant assist только admin/chief_admin. Помощник по умолчанию выключен. Он предлагает simple-form v1; подготовка пакета, CLI и активация выполняются отдельно обычными действиями редактора. Применение предложения требует явного действия, подтверждает замену несохранённого ввода и возвращает режим CLI.

Конфигурация оператора:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| SMC_STUDIO_ASSISTANT_ENABLED | false | Разрешить вызовы настроенного провайдера |
| SMC_STUDIO_ASSISTANT_PROVIDER | none | Код SPI; встроенный openai-compatible |
| SMC_STUDIO_ASSISTANT_ENDPOINT | пусто | Полный HTTPS URL Chat Completions endpoint без query/userinfo/fragment |
| SMC_STUDIO_ASSISTANT_MODEL | пусто | Явный идентификатор проверенной модели |
| SMC_STUDIO_ASSISTANT_API_KEY | пусто | Bearer secret через окружение/secret store; пусто только для gateway, которому он не нужен |

Сетевой транспорт использует JSON mode и store=false; поддержка этих полей конкретным gateway проверяется до включения. Это не гарантия retention поставщика. Запрос содержит только явно введённый prompt и фиксированную инструкцию формата. Не вводите персональные данные и секреты. Строки существующих записей, файлы и metadata клиента не подмешиваются автоматически. Ни вход, ни ответ не сохраняются сервером, не пишутся в логи и не попадают в idempotency replay; общий клиентский retry для этого пути отключён.

Ограничения: prompt 1–2000 Unicode code points, HTTP body 16 KiB; response envelope 64 KiB, декларация 32 KiB и обычный строгий validator. Не больше двух запросов на процесс; бюджет пользователя на одном процессе 5/минуту с burst 2, timeout 30 секунд, connect timeout 5 секунд. Автоматических повторов нет. Провайдер, игнорирующий interruption, удерживает слот до завершения; этим ограничивается накопление фоновых задач. Права, session/authentication generation и модуль повторно проверяются после ответа. Модель не получает tools, не исполняет SQL и не создаёт форму.

GET /api/v1/studio/assistant возвращает available; POST /api/v1/studio/assistant/drafts принимает только prompt и возвращает несохранённую декларацию (200, Cache-Control:no-store). Неизвестный/неполный prompt — 422, слишком большое тело — 413, доступ — 401/403/404, занятость — 429, disabled/provider/timeout/invalid output — 503. Клиент сохраняет задание и предлагает ручной повтор; поздний результат прежнего контекста не применяется.

Метрика smc.studio.assistant.requests с bounded outcome показывает success/invalid/timeout/interrupted/failed/discarded; журналы содержат только тип исхода, без тела или секретов. При росте отказов выключите флаг, проверьте endpoint/model/квоту и доступность gateway без клиентских данных. Не включайте HTTP wire logging для диагностики.

## Приёмка и откат

Перед включением: согласовать провайдера/модель, обработку и retention данных, бюджет и egress; настроить secret; выполнить один synthetic smoke, проверить отказ прав, latency, ошибки и выключение. При нескольких репликах общий финансовый лимит/квота задаётся на gateway: процессные лимиты приложения не являются общей квотой. Локальные HTTP fixtures не подтверждают конкретный cloud/self-hosted gateway. Сейчас реальная отправка наружу и расходы не выполнялись.

При проблемах задайте SMC_STUDIO_ASSISTANT_ENABLED=false и перезапустите все реплики: флаг читается при старте приложения. Данные при этом не меняются. Обратный выпуск приложения требует проверить новые сохранённые chart/dataset значения: старый код их не поддерживает. Автоматического downgrade сохранённых определений нет. Связанный target архивируется/отзывается обычными механизмами, dataset пересчитывает текущую видимость. Переносимость наборов зависит от объявленного кода соответствующего модуля.

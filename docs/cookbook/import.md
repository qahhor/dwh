# Рецепт: импорт из xlsx

**Эталон:** справочник `example.products` (импорт по коду); документ
`example.orders` (импорт шапки по номеру из последовательности).

## Цель

Кнопка «Импорт» в общем списке: шаблон xlsx по полям, которые зритель может
писать; строка файла находит запись по ключу (изменение) или создаёт новую;
ошибки — по строкам и полям (`rows[3].unit`). Своего кода импорта нет
(ADR-0032, §10.1).

## Команда

Отдельной команды нет: одна строка объявления, право `import` в
`.rights(...)` и в миграции прав, уникальный индекс по ключу.

| Путь | Что |
|---|---|
| `GET /api/v1/entities/<код>/import-template` | шаблон: записываемые поля, которые зритель видит |
| `POST /api/v1/entities/<код>/imports` | ставит в очередь импорт загруженного файла: проверку без записи или запись (202 + `Location`) |
| `GET /api/v1/imports/{id}`, `GET /api/v1/imports/{id}/report` | состояние и отчёт по строкам |

## Тест

Группа кита «import» появляется сама у сущности с `importKey`: шаблон по
правам, проверка без записи, upsert по ключу, ошибки `rows[n].поле`, запись вне
скоупа не меняется. `EntityImportDeclaredTest` требует уникальный индекс по
колонке ключа.

## Подводные камни

- Ключ — текстовое поле формы в своей колонке; индекс по выражению
  (`lower(code)`) проверка не примет.
- Ключ, который даёт сервер (номер из последовательности, как у заказов),
  только для чтения: строка с номером находит запись, строка без номера создаёт
  новую со своим номером.
- В шаблон не входят файлы, JSON, поля «только для чтения», строки документа и
  доп. поля администратора.
- Импортированная строка — то же `CREATE` или `UPDATE` для хуков
  (`save.imported()` — `true`), аудит пишет источник `import`.
- Права: `import` и ещё `create` или `update` на каждую строку.

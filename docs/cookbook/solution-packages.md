# Рецепт: перенести решение / создать из шаблона

Основание: [ADR-0047](../adr/ADR-0047-solution-packages-and-templates.md); формы — [ADR-0038](../adr/ADR-0038-live-simple-forms.md)
и [ADR-0041](../adr/ADR-0041-live-form-evolution.md), рассылки — [ADR-0045](../adr/ADR-0045-report-mailings.md),
автоматизации — [ADR-0046](../adr/ADR-0046-live-form-automations.md).

## Цель

Решение, собранное в Studio одной установки — живые формы со справочниками, наборами данных, отчётами, рассылками и
автоматизациями, — разворачивается в другой установке за один приём: загрузка пакета, проверка, сопоставление ролей и
получателей, применение. Готовые решения ставятся из галереи шаблонов так же.

## Подготовка

1. Модуль `studio` включён, создание живых форм разрешено (`SMC_STUDIO_ACTIVATION_ENABLED=true` на всех узлах).
2. Права `studio.packages` — `export` (выгрузка) и `import` (загрузка, применение, шаблоны); у административных ролей
   они есть сразу (V238). Применение требует ещё прав каждого вида элементов: `studio.forms.publish`,
   `studio.lists.manage`, `md.report_datasets.manage`, `md.profile.update` (отчёты), `md.settings.update` (доступ
   отчёта ролям), `report.mailings`, `studio.automations.manage`, `md.roles.grant` (права ролям); без права элемент
   отказан с причиной.

## Перенести решение

1. **Выгрузить** в исходной установке: «Настройки → Пакеты и шаблоны → Выгрузка пакета». Код (`orders-approval`),
   версия (`1.0.0`), название ru/uz/en, формы решения; «Справочники со значениями» — по умолчанию да. «Показать
   состав» перечисляет, что войдёт и почему: формы и справочники, на которые ссылаются выбранные формы, — сами; ниже —
   наборы данных, отчёты, рассылки и автоматизации, которые используют эти формы, — отметьте нужные и покажите состав
   снова. Роли с правами на формы и фиксированные получатели станут подстановками. «Скачать пакет» сохраняет файл
   `<код>-<версия>.json` с контрольной суммой.
2. **Загрузить** в целевой установке: «Пакеты и шаблоны → Загрузка пакета», файл и, для второй копии того же решения,
   суффикс (`_b`: коды форм, справочников и наборов получат его). «Проверить пакет» ничего не меняет: открывается
   страница загрузки с результатом по каждому элементу — «Создать», «Изменить» (новая версия существующей формы с тем же
   кодом по правилам совместимости; недостающие значения справочника), «Без изменений», «Пропустить» или «Отказано» с
   причиной.
3. **Сопоставить**: каждой роли пакета — роль этой установки (без выбора права не выдаются), получателям рассылки —
   пользователей (обязательно). «Проверить сопоставление» повторяет проверку с выбором.
4. **Применить** с подтверждением: всё или ничего. Отказ хоть одного элемента — ничего не изменено, причины в таблице.
   После применения рассылки и автоматизации **приостановлены**: откройте их («Автоматизации», «Отчёты → Рассылки»),
   проверьте и включите — автоматизация будет работать от имени включившего.

Повторная загрузка того же пакета — все элементы «Без изменений», применение ничего не создаёт; новая версия пакета
меняет только изменённые элементы (изменённые рассылки и автоматизации снова приостанавливаются).

## Создать из шаблона

«Пакеты и шаблоны → Шаблоны»: «Визит торгового представителя», «Заявка клиента», «Заказ со строками и согласованием»
(отчёт «Заказы по регионам» с еженедельной рассылкой, автоматизация согласования). «Создать из шаблона» — та же
проверка, сопоставление («Торговый представитель», «Согласующий», получатели рассылки) и применение.

## Через API

Без интерфейса — те же шаги (cookie сессии и `X-XSRF-TOKEN`, без `Idempotency-Key`):

```bash
# выгрузка
curl -X POST "$BASE/api/v1/studio/packages/export" -H 'Content-Type: application/json' \
  -d '{"code":"orders-approval","version":"1.0.0","title":{"ru":"Заказы","uz":"Buyurtmalar","en":"Orders"},"forms":["studio.orders"]}' \
  -o orders-approval-1.0.0.json
# загрузка и проверка: 201 и Location /api/v1/studio/packages/imports/{id}
curl -X POST "$BASE/api/v1/studio/packages/imports?suffix=_b" -H 'Content-Type: application/json' \
  --data-binary @orders-approval-1.0.0.json
# применение с сопоставлением; "dryRun": true — только проверка
curl -X POST "$BASE/api/v1/studio/packages/imports/7/apply" -H 'Content-Type: application/json' \
  -d '{"mapping":{"role-1":[4],"mailing-12":[31,32]}}'
# шаблон
curl -X POST "$BASE/api/v1/studio/templates/order-approval/imports"
```

## Тест

`SolutionTemplateFilesTest` читает каждый шаблон как загрузку; `StudioPackageHttpTest` проверяет перенос под новыми
кодами, повтор без изменений, изменённый файл, несовместимую форму, значения записей и права; e2e
`studio-packages.spec.ts` — то же на живом стенде с ролями, согласованием и включением автоматизации.

## Подводные камни

- Значение фильтра или параметра отчёта, которое ссылается на запись, пользователя или подразделение, в пакет не
  попадает — выгрузка отказывает с адресом: уберите его из фильтра или параметров (коды справочников переносятся).
- Записи не переносятся; подписки на вебхуки — интеграции установки с адресом и секретом — тоже.
- Форма с тем же кодом, но несовместимой декларацией (другой тип поля, удалённый вариант) отказывается с причиной;
  нужна новая форма (суффикс) или выгрузка в код.
- Лимит 100 активных живых форм действует и для пакета: архивируйте ненужные формы перед загрузкой.
- После правки шаблона в ресурсах пересчитайте суммы: `-Dtest=SolutionTemplateFilesTest -Dtemplates.update=true`.

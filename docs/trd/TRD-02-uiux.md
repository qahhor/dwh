# ТЗ-02: UI/UX — корпоративный минимализм

**Версия:** 0.1
**Дата:** 2026-08-27
**Статус:** На ревью у CEO
**Основание:** ТЗ-01 v0.7 (экраны и блоки), ADR-0012 (UI-фундамент), направление CEO: «корпоративный сегмент, минималистичный дизайн»
**Принцип документа:** каждый блок завершается строкой **Результат** — проверяемым исходом; сводка — в §12.

---

## 1. Аудитория и контекст использования

| Роль | Где работает | Что важно |
|---|---|---|
| Админ клиента | Десктоп, долгие сессии | Плотность информации, скорость операций, поиск |
| Менеджер / исполнитель задач | Десктоп, периодически планшет | «Мои задачи» с одного взгляда, уведомления |
| Наш инженер (control plane) | Десктоп | Флот-дашборд: аномалии видны за секунды |

Устройства: **desktop-first**. Полная поддержка ≥ 1280px; работоспособность на 1024px;
планшет (768px) — чтение и задачник; мобильные телефоны — вне объёма Этапа 1.

**Результат:** каждый экран Этапа 1 имеет назначенную роль-владельца и проверяется на 1280px и 1024px.

## 2. Дизайн-принципы (корпоративный минимализм)

1. **Плотность вместо воздуха.** Это рабочий инструмент на 8 часов, а не лендинг: компактные
   таблицы, без декоративных пустот и иллюстраций.
2. **Один акцентный цвет.** Всё остальное — нейтральная шкала; цвет несёт смысл
   (действие/состояние), а не украшение.
3. **Иерархия — типографикой и отступами,** не рамками и заливками. Тени — максимум один
   уровень (overlay-элементы).
4. **Ноль декоративной анимации.** Переходы только функциональные (открытие панели, скелетон), ≤ 200 мс.
5. **Состояние всегда видно:** у каждой сущности — статус-чип; у каждого списка — пустое
   состояние с действием; у каждой операции — исход (тост/inline-ошибка).
6. **Предсказуемость важнее оригинальности:** одинаковые задачи решаются одинаковыми паттернами (§5).

**Результат:** принципы применяются как чек-лист ревью каждого экрана; отступление фиксируется письменно в PR.

## 3. Дизайн-токены (единственный источник стиля)

Токены живут в коде (`libs/ui-tokens`), UI использует только их (ADR-0012, stylelint в CI).

| Группа | Значения |
|---|---|
| **Цвет: нейтрали** | 10-ступенчатая серая шкала с лёгким холодным сдвигом (fon: `#FAFBFC` свет / `#111417` тьма — финальные значения калибруются на `/ui-kit`) |
| **Цвет: акцент** | Один. Предварительно глубокий сине-серый (**подтвердить у CEO — возможна привязка к бренду Smartup**) |
| **Цвет: семантика** | success / warning / danger / info — приглушённые, применяются только к статусам и алертам |
| **Типографика** | Inter (self-hosted); шкала: 12 / 13 / 14 (базовый) / 16 / 20 / 24; вес 400/500/600; `tabular-nums` для чисел в таблицах |
| **Сетка и отступы** | Базовый шаг 8px (плотные ряды таблиц — 4px); контейнеры 12-колоночные |
| **Радиусы** | 4px поля/кнопки, 8px карточки/диалоги — всё |
| **Тени** | Одна, только для overlay (меню, диалоги) |
| **Темы** | Светлая — обязательная и дефолтная; тёмная — S (токены закладываются сразу, калибровка — M5) |

**Результат:** страница `/ui-kit` отображает все токены и обёртки; прямой hex/px в коде компонентов ломает CI.

## 4. UI-фундамент

Angular Material + CDK со строгой темой из токенов; обёртки `ui-*`; Material Symbols; Inter.
Решение и правила — **ADR-0012** (дефолтная тема Material запрещена; компонентный зоопарк запрещён).

**Результат:** все экраны Этапа 1 построены только из обёрток `ui-*`; факт проверяется ревью + отсутствием прямых импортов Material-компонентов вне `libs/ui` (ArchUnit-аналог для фронта — eslint-правило).

## 5. Каркас приложения и паттерны

### 5.1. App shell

Левая навигация (собирается из эффективных прав — FR-PERM-9; сворачиваемая, иконки+текст),
верхняя панель: глобальный поиск (S), колокольчик с бейджем, переключатель языка, профиль.
Баннер объявлений — над контентом, закрываемый. Хлебные крошки — на вложенных экранах.

### 5.2. Обязательные паттерны (одинаковые везде)

| Паттерн | Требование |
|---|---|
| **Таблица-грид** | Сортировка, фильтры в шапке, keyset-пагинация «Загрузить ещё», выбор строк для массовых операций, колонки по правам (FR-PERM-11), сохранение состояния фильтров в URL |
| **Форма** | Валидация inline при blur + сводка ошибок сверху при submit; ошибки сервера (problem+json) мапятся на поля; несохранённые изменения — предупреждение при уходе |
| **Карточка сущности** | Заголовок + статус-чип + действия справа; вкладки при > 2 разделах |
| **Опасные действия** | Подтверждение с именем объекта; необратимые — ввод имени объекта |
| **Пустые состояния** | Иконка + одна фраза + основное действие; никогда просто «Нет данных» |
| **Загрузка** | Скелетоны для страниц, спиннер только внутри кнопок; операции > 2 с — прогресс с отменой, где возможна |
| **Исход операции** | Тост 4 с (успех) / inline-ошибка (провал); формулировки — «что произошло», не коды |

**Результат:** паттерны реализованы как обёртки/директивы один раз; новый экран не пишет собственную таблицу или валидацию — проверяется ревью.

## 6. Каталог экранов Этапа 1 (по вехам, с результатами)

| Веха | Экран | Точный результат приёмки |
|---|---|---|
| M1 | Вход (+OTP-шаг), восстановление пароля | Полный цикл входа с клавиатуры без мыши; ошибки не раскрывают, существует ли логин |
| M1 | Профиль, мои сессии | Завершение чужой сессии отражается у неё ≤ 60 с |
| M1 | Пользователи: список + карточка | Создание пользователя ≤ 60 с от кнопки до строки в гриде; блокировка мгновенно видна в списке |
| M2 | Роли: список + матрица прав (дерево форм × действия) | Выдача роли с 50 правами — одним сохранением; поиск по дереву форм |
| M2 | «Права глазами пользователя» | Для любого пользователя виден источник каждого права (роль/личное) |
| M3 | Центр уведомлений + колокольчик | Новое уведомление появляется без обновления страницы p95 ≤ 5 с |
| M3 | Настройки каналов (привязка Telegram) | Привязка по deep-link ≤ 3 действий пользователя |
| M3 | Объявления (баннер + лента) | Непрочитанное объявление видно при входе; отметка синхронизируется |
| M3 | **CP:** клиенты, флот-дашборд, лицензии, объявления | Аномалия (нет heartbeat, провал бэкапа, отставание версии) различима на дашборде ≤ 10 с взгляда — цветовая кодировка состояний |
| M4 | Задачи: «Мои задачи», список проекта, карточка задачи | Смена статуса и комментарий — без ухода со списка (панель-детали); карточка держит 200+ комментариев без деградации |
| M4 | Файлы в задаче | Drag&drop, прогресс, превью изображений |
| M5 | Аудит, security-журнал, dead-letter | Сценарий «кто изменил права X» ≤ 2 мин (результат AUD из ТЗ-01 §8.2) |
| M5 | Настройки экземпляра, `/ui-kit` | `/ui-kit` показывает 100% обёрток и токенов |

**Результат:** экран принимается только по своей строке; экраны без строки в каталоге не разрабатываются.

## 7. Доступность

WCAG 2.1 AA как планка: контраст ≥ 4.5:1 (текст) / 3:1 (крупный, иконки-статусы),
полная работа с клавиатуры (таблицы и меню — по паттернам ARIA, это даёт CDK), видимый фокус,
`aria`-разметка форм и живых областей (тосты, колокольчик), цвет никогда не единственный
носитель смысла (статус = цвет + текст/иконка).

**Результат:** axe-core прогон в CI на ключевых экранах — 0 критических нарушений; вход и «Мои задачи» проходимы вслепую с клавиатуры (ручная проверка в M5).

## 8. Язык интерфейса и тексты

ru/uz(лат)/en по ключам (FR-I18N-1); формулировки — по глоссарию терминов ТЗ-01 §2 (единые
слова: «экземпляр», «роль», «право», «объявление»); даты/числа — по локали пользователя,
время — в его поясе с подсказкой пояса у критичных полей (сроки задач). Тексты ошибок:
что случилось + что делать; без «Ошибка №500».

**Результат:** CI-проверка полноты ключей (0 пропусков); глоссарий — часть ревью текстов.

## 9. Производительность фронтенда

| Метрика | Бюджет |
|---|---|
| Initial bundle (gzip) | ≤ 350 КБ (lazy-загрузка модулей по маршрутам) |
| LCP первого экрана после логина | ≤ 2,0 с на профиле M |
| Взаимодействие (INP) | ≤ 200 мс |
| Грид 10 000 строк | Прокрутка без фризов (виртуализация CDK) |

Change detection: OnPush/signals везде; состояние — без тяжёлых сторонних стор-библиотек
(signals + сервисы; решение о NgRx — только при доказанной необходимости, отдельным мини-ADR).

**Результат:** бюджеты проверяются в CI (size-limit) и в нагрузочном прогоне M5.

## 10. Процесс дизайна (команда без дизайнера)

Код-first: дизайн-система живёт в `/ui-kit`, макеты в Figma не являются источником истины.
Для новых сложных экранов — быстрый wireframe (можно от руки/в FigJam) → ревью CEO/владельца
продукта → реализация обёртками. Владелец UI-кита — один человек (FE-senior), правки токенов
и обёрток — только через него.

**Результат:** у UI-кита есть назначенный владелец; каждый экран M1+ прошёл wireframe-ревью до реализации.

## 11. Вне объёма Этапа 1

Мобильные телефоны · тёмная тема как обязательство (S) · брендирование под клиента
(white-label — отдельное решение при спросе) · дашборды-конструкторы (Этап 3) ·
анимированный онбординг · кастомизация интерфейса пользователем (кроме языка/пояса).

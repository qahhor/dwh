# План доведения SmartupCMS до релиза

> Для исполнителя: выполнять задачи последовательно по `superpowers:executing-plans`;
> исправления поведения проверять через `superpowers:test-driven-development`.
> Начальный пакет исправлений выполняется по поручению владельца от 2026-10-11.

**Цель:** подготовить проверяемый release candidate SmartupCMS и доказательства
приёмки конкретной установки без изменения текущей архитектуры.

**Архитектура:** модульный монолит, общий runtime сущностей, одна организация
на установку, PostgreSQL, warehouse, очередь jobs и transactional outbox.
Исправления используют существующие API, каталоги переводов и средства приёмки.

**Стек:** Java 25 / Spring Boot 4.1, Angular 22, PostgreSQL 18, Docker Compose.

**Основание:** [ТЗ](../technical-specification.md), [план 10/10](../plan-10-10.md),
[AGENTS.md](../../AGENTS.md), [checklist установки](production-launch-checklist.md).
Этот документ задаёт порядок работ, а не заменяет требования или результаты тестов.
Исходная точка — `main`, `d406d696`; отсутствие результата означает «не подтверждено».

## Ограничения и порядок

- P0 блокирует production. P1 — следующая очередь исправлений и улучшений;
  приоритет не разрешает обходить обязательные FR/NFR/AC из ТЗ.
- Первым выполняется небольшой пакет P1-01/P1-02: подтверждённые дефекты
  документации и локализации. Затем P0-01…P0-06 на фиксированном кандидате.
- Каждое последующее изменение кода требует актуализировать затронутые
  доказательства; полный обязательный CI выполняется на окончательном SHA.
- Одна ветка на пакет от `main`; никаких изменений выпущенных миграций,
  понижения coverage floors или расширения baseline. До финального выпуска
  нет клиентских установок и не нужны переходные API либо миграции их данных.
- Тяжёлые проверки — по одной. Установка пакетов, внешние изменения,
  публикация, merge и операции с данными требуют отдельного разрешения.
- Продолжение от 2026-10-11 включает P0-02 и исправление подтверждённых ошибок
  проверок. Production drills, публикация и решения владельца из P0-01
  не считаются выполненными этим пакетом.
- Владелец разрешил загрузку и установку необходимых зависимостей CI
  (2026-10-11). Публикация, merge и изменение внешних правил доступа этим
  разрешением не охватываются.

## Критические условия проверки

1. Обычная форма матрицы прав должна переводиться так же, как сущность runtime;
   неизвестные записи сохраняют исходные подписи — P1-02.
2. Переключение языка меняет подписи и поиск в матрице, не изменяя выданные права — P1-02.
3. Отзыв доступа, скрытое поле и чужой ID действуют также в истории, экспорте,
   поиске и нестандартных эндпоинтах — P0-03.
4. Потеря lease и остановка между записью warehouse и сменой статуса не дают
   недопустимых повторных эффектов — P0-04.
5. Потеря хоста требует восстановить обе БД, байты объектов и ключи;
   успешное восстановление только одной БД не закрывает приёмку — P0-04.

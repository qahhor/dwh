# Контракт декларации формы: прототип Студии

Это контракт декларации STU-01 из [плана Студии](admin-studio-plan.md), дополненный жизненным циклом STU-02 в последнем разделе. Активации рабочей формы он не выполняет. Он меняет только представление существующей формы `example.products`. Схема данных, `EntityDefinition`, hooks, права, EntityRuntime и физические таблицы сохраняются.

- [JSON Schema 2020-12](../api/form-layout.schema.json) описывает форму документа.
- [Пример декларации](../api/form-layout.example.json) переименовывает поле, переставляет поля и добавляет секцию.
- Серверная проверка — обязательный источник решения о допустимости. Одной JSON Schema недостаточно для проверки актуальных полей, прав и лимита в байтах.

## Пользователь и сценарий

Администратор с `md.settings.update` открывает «Настройки → Студия форм», настраивает подписи ru/uz/en, порядок и секции формы «Товары», проверяет результат и скачивает JSON. Импорт файла проходит ту же серверную проверку до замены текущего черновика. Если модуль `example` отключён или отсутствует `example.products.view`, форма недоступна.

Предпросмотр использует `SMTEntityFormComponent` и синтетические значения в памяти страницы. Кнопки сохранения записи нет. Выход с несохранёнными изменениями требует подтверждения. STU-01 сохраняет проверенную декларацию в файл; STU-02 отдельно сохраняет общий черновик в БД. Файл можно импортировать обратно. Обычная форма и бизнес-данные не меняются; активного layout в БД нет. Серверные черновики и подготовленные версии описаны в разделе STU-02 ниже.

## Формат v1

| Поле | Правило |
|---|---|
| `formatVersion` | Целочисленный JSON-токен `1` (не `1.0`/`1e0`); версия формата, не ревизия записи или определения |
| `kind` | Только `form-layout`; отчёты и дашборды получат отдельные контракты |
| `entityCode` | Только `example.products` в этом прототипе |
| `sections` | Упорядоченный массив от 1 до 8 непустых секций |
| `sections[].id` | Стабильный ID секции, `[a-z][a-z0-9_]{0,39}`, уникален в документе |
| `sections[].labels` | Необязательный объект с ровно `ru`, `uz`, `en`. Для новой секции обязателен; без него существующая секция наследует подпись |
| `sections[].fields` | Упорядоченный массив ссылок на поля, суммарно не более 64 |
| `fields[].fieldId` | Существующий ключ поля, уже включённого в доступный layout; не имя колонки и не новая сущность |
| `fields[].labels` | Необязательные подписи ровно ru/uz/en; отсутствие сохраняет исходную подпись |

Каждая подпись — непустой текст до 120 символов без управляющих и невидимых форматирующих символов Unicode; HTML не интерпретируется. Длину сервер считает в Unicode code points; эта семантическая проверка дополняет JSON Schema. Переименование меняет только отображение: `fieldId`, тип, обязательность, readonly, defaults, conditions, данные и ссылки отчётов остаются исходными.

Все доступные поля исходного layout должны присутствовать ровно один раз. Удаление обязательного поля, дубликат, неизвестное или скрытое поле отклоняются. Системное поле `modifiedAt`, не включённое в исходный layout, добавить нельзя. Поля metadata за пределами layout остаются в исходном metadata, но редактор не делает их редактируемыми.

## Валидация и безопасность

Максимум документа — **32 768 байт UTF-8**, глубина JSON — **8**. Сервер ограничивает чтение до разбора, отклоняет дублирующиеся ключи, trailing JSON, невалидный JSON и несоответствие типов. Во всех объектах действует закрытый список свойств. Входные `$ref`, `$defs`, `operator`, `type`, `required`, `readonly`, SQL, URL источника и любые другие неописанные свойства запрещены. Поэтому циклическая и сетевая ссылка отвергаются как недопустимая конструкция; разрешения ссылок, загрузки схем, вычисления выражений или исполнения кода нет.

Внутренние `$ref` в опубликованном файле JSON Schema служат документации формата, а не разрешают ссылки во входных декларациях. Проверка preview не пишет БД, не выполняет CRUD и не изменяет глобальный registry/cache.

Каждый запрос проверяет право настройки, затем модуль и право просмотра сущности. Metadata строится заново с текущими правами полей. Успешная предыдущая проверка не даёт права на следующую. Ошибка имеет стандартный `application/problem+json`, код и i18n-ключ; пользовательский JSON и значения полей не попадают в сообщение или лог.

## HTTP-контракт

| Метод / путь | Результат |
|---|---|
| `GET /api/v1/form-studio/prototype` | `200 {declaration, meta}`: исходный layout и доступный FormMeta |
| `POST /api/v1/form-studio/preview` | Принимает декларацию JSON; `200 {declaration, meta}` только после проверки |

`meta` — исходный, отфильтрованный сервером FormMeta. UI делает отдельную копию для предпросмотра: подписи выбранного языка и порядок из декларации; остальные правила берёт из metadata. Исходный metadata и кэш не изменяются. Неавторизованный запрос — 401; отсутствие административного права — 403; выключенная/недоступная форма — 404. Ошибка документа — структурированный 4xx. `Idempotency-Key` для preview не поддерживается: ответ и декларация не должны сохраняться в журнал повторов. Клиент не добавляет этот заголовок; каждый запрос повторно проверяет доступ. `If-Match` не нужен, поскольку endpoint не изменяет revisioned records. В STU-02 контроль ревизий обязателен для обновления серверного черновика и подготовки версии.

После изменения настройки предыдущая проверка и экспорт теряют силу. Неуспешный импорт сохраняет текущий черновик. При ошибке загрузки доступны объяснение и повтор; ошибка не выдаётся за пустой результат.

## Жизненный цикл STU-02

[ADR-0035](../adr/ADR-0035-declaration-lifecycle.md) расширяет прототип серверным черновиком и неизменяемым пакетом. Контракт декларации v1 выше сохраняется. Подготовка пакета не активирует рабочую форму. В БД сохраняется только декларация, прошедшая прежнюю строгую проверку; незавершённое редактирование остаётся локальным до исправления ошибок. «Черновик» здесь означает неопубликованный, а не произвольный невалидный JSON.

Здесь `{code}` — код поддерживаемого прототипа, а `{version}` — номер неизменяемой версии. Доступ заново проверяется для каждого запроса; GET отсутствующего черновика отличается от недоступной формы.

| Метод / путь после `/api/v1/form-studio` | Результат |
|---|---|
| GET `/drafts/{code}` | 200 `{draft: null или {entityCode, revision, declaration}, meta}` |
| POST `/drafts/{code}` | Сырая декларация → 201, Location, ETag; повторное создание → 409 |
| PUT `/drafts/{code}` | Сырая декларация + If-Match → 200 и новая ревизия/ETag; 428 без ревизии, 409 при конфликте |
| POST `/drafts/{code}/versions` | If-Match сохранённого черновика → атомарно подготовленная версия с пакетом; повтор той же текущей ревизии безопасен |
| GET `/drafts/{code}/versions` | Страница истории, default limit 20, максимум 100; превышение → 422 |
| GET `/drafts/{code}/versions/{version}` | Неизменяемый конверт версии и пакета после повторной проверки доступа |
| POST `/drafts/{code}/versions/{version}/verify` | Сырой JSON-конверт → подтверждение целостности и актуальности зависимостей; никаких изменений runtime |

Документирующая [JSON Schema конверта](../api/form-layout-package.schema.json) дополняет OpenAPI; авторитетна серверная проверка. Ответ версии: `{version, sourceRevision, checksum, package}`. В `package`: `formatVersion: 1`, `kind: "form-layout-package"`, `entityCode`, `version`, `sourceRevision`, `dependencies: {contractVersion: 1, metadataChecksum}` и `declaration`. Числовые идентификаторы не превышают диапазон точных целых JSON/JavaScript. Контрольная сумма вычисляется по содержимому package, а сервер дополнительно сравнивает его с сохранённой доверенной версией. Изменить декларацию и пересчитать checksum недостаточно для прохождения проверки.

Пакет проверяется только в установке с сохранённой исходной версией: перенос между окружениями ещё не является поддержанным импортом. Размер конверта ограничен 64 KiB, вложенной декларации — прежними 32 KiB; неизвестные свойства, неверные типы, duplicate keys и trailing JSON запрещены. Права/зависимости могут измениться после подготовки: успешная старая проверка не даёт права на новый доступ.

POST/PUT Студии помечены `@NoIdempotency`: клиент не добавляет Idempotency-Key, переданный ключ отклоняется. Идемпотентность подготовки обеспечивает хранилище версий, не HTTP replay. Стандартный аудит фиксирует серверные изменения.

UI различает локальную декларацию и сохранённый снимок. Экспорт JSON не меняет статус сохранения в БД. При конфликте ввод сохраняется; перечитать серверную версию можно явно, с подтверждением потери локальных изменений. Изменение зависимостей пакета выделено отдельно от конфликта ревизии: интерфейс разрешает явно сохранить прежний layout в новую ревизию, затем подготовить пакет. Выбор/скачивание/проверка пакета не заменяет текущий черновик.


## Новые простые формы: контракт STU-04

Это отдельный контракт от `form-layout`: [ADR-0037](../adr/ADR-0037-simple-form-cli-delivery.md), [JSON Schema](../api/simple-form.schema.json), [пример](../api/simple-form.example.json), [доставка](../cookbook/simple-form-delivery.md).

`POST /api/v1/form-studio/new-forms/prepare` принимает `simple-form` v1 и отвечает `200` пакетом `{formatVersion:1,kind:"simple-form-package",declaration,checksum}`. Требуется актуальное `md.settings.update`; `Idempotency-Key` не поддерживается, `If-Match` не требуется для операции без состояния. Ответ `no-store`. Модуль «Примеры» и просмотр его форм не требуются.

| Часть | Ограничение |
|---|---|
| Декларация | UTF-8 ≤32768 байт, глубина ≤8, только известные свойства, без дубликатов ключей и второго JSON-значения |
| Пакет CLI | UTF-8 ≤65536 байт, глубина ≤10; декларация после канонизации отдельно ограничена 32768 байтами/8 уровнями |
| Числа формата/ограничений | Целочисленные JSON-токены, без дробной/экспоненциальной записи |
| `module` | `{code,title}`; code `[a-z][a-z0-9]{1,11}`, без ключевых слов Java и имён устройств Windows |
| `entity` | `{name,title}`; name `[a-z][a-z0-9_]{0,19}` |
| Название/подпись | `{ru,uz,en}`, каждый текст 1…80 Unicode code points, без крайних пробелов, управляющих/format-символов, U+2028/U+2029 и одиночных суррогатов |
| `fields` | 0…20 дополнительных полей в порядке формы; уникальный `id` `[a-z][a-z0-9]{0,19}`, `type`, `labels`, boolean `required` и `listed` |
| text/textarea | Обязателен `maxLength` 1…4000; `scale` запрещён |
| number | Обязателен `scale` 0…6; `maxLength` запрещён |
| date/datetime/time/bool/email/phone/url | Без дополнительных свойств типа; datetime — момент ISO-8601 с offset/Z; используется существующий общий renderer и PostgreSQL timestamptz |
| Зарезервированные поля | `name`, `code`, `id`, `revision`, `attributes`, `archived`, `archivedat/by`, `createdat/by`, `modifiedat/by`, системные колонки PostgreSQL, SQL keywords R/T и `constructor`; [общий список сервера/CLI](../../apps/server/src/main/resources/studio/simple-form-reserved-identifiers.json) |

SHA-256 вычисляется по UTF-8 JSON декларации с рекурсивно отсортированными ключами объектов, неизменным порядком массивов и без пробелов. Это checksum целостности, не цифровая подпись. Сервер не знает актуального checkout доставки: окончательную проверку коллизий выполняет CLI. Пакет не содержит произвольных файлов, путей, URL зависимостей или исполняемого кода. Произвольные новые поля JSON не игнорируются.

Скачанный локальный черновик — декларация, пакет — результат успешной проверки. Новая схема не сохраняется в таблицы STU-02 и не активирует runtime. CLI допускает только создание, все изменения уже доставленной схемы блокирует; schema-revision handshake и анализ преобразования существующих данных остаются отдельным этапом.


### Восстановление незавершённого ввода

`POST /api/v1/form-studio/new-forms/check-draft` проверяет только закрытую структуру [локального черновика](../api/simple-form-draft.schema.json), UTF-8, размер, глубину и типы. Право `md.settings.update`, запрет replay и `no-store` те же. Идентификаторы и названия могут быть пустыми/незавершёнными (строки ≤80 символов, без управляющих/format-символов); числовые ограничения могут отсутствовать, быть null или конечным числом, включая ещё неверное дробное/отрицательное значение. Типы полей и boolean-флаги уже должны быть известными и корректными. Повторяющиеся идентификаторы полей допускаются как незавершённый ввод; дубли JSON-ключей запрещены.

Ответ — только декларация для заполнения редактора, без checksum. После импорта пакет и предпросмотр не считаются подготовленными. Отдельный `prepare` снова проверяет полную схему, уникальные/незарезервированные ID, подписи и целочисленные допустимые ограничения. [Схема пакета](../api/simple-form-package.schema.json) никогда не допускает незавершённые значения. Это позволяет сохранять и открывать черновик без ослабления доставки.

## STU-05: ограниченная активация simple-form-package

[ADR-0038](../adr/ADR-0038-live-simple-forms.md) расширяет способы доставки
пакета STU-04. `GET /api/v1/studio/activation` сообщает доступность и лимиты;
`POST /api/v1/studio/forms` принимает пакет до 64 KiB и возвращает 201,
`Location` metadata, `entityCode` и checksum. Нужно отдельное
`studio.forms.publish`; UI редактора по-прежнему требует `md.settings.update`.
Запрос с `Idempotency-Key` запрещён: точный повтор проверяется по содержимому
в транзакции, изменённый пакет существующего кода даёт 409. Успешная активация
не выдаёт автору CRUD: начальные grants только admin/chief_admin.

Только namespace `studio.*`, до 100 форм, до 20 дополнительных полей прежних
10 типов. Имена `forms`, `records`, `activation` зарезервированы. Общий список
идентификаторов дополнен фрагментами секретов (password/passwd/secret/apikey/
privatekey/accesstoken/refreshtoken): отказ происходит при prepare и в CLI,
а не как ошибка runtime. Неизвестный/чужой код не раскрывает существование записи.

Определения create-only и неизменяемы; DDL на запросе нет. Внутри HTTP-запроса
все consumers читают один snapshot из БД. API metadata является контрактом
динамической формы; статический OpenAPI содержит API активации и общие DTO,
генерации нового TypeScript-типа для каждой активированной формы нет.
Загрузка JSON-черновика всегда возвращает редактор в безопасный режим CLI.
При неопределённом результате сети повторяется тот же пакет; при сбое refresh
после успешной активации повторяется только обновление прав/меню/подписей.

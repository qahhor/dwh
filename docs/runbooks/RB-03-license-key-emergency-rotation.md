# Runbook RB-03: Экстренная ротация закрытых ключей подписи лицензий

**Версия:** 1.0
**Основание:** ADR-0008, TRD-04 разд. 6.2 (валидация лицензии по `kid`).
**Актор:** Инженер информационной безопасности.

---

## 1. Сценарий применения

- Компрометация закрытого ключа подписи лицензий в Vault Transit.
- Плановая ежегодная ротация криптографических ключей платформы.

---

## 2. Порядок безопасной ротации без прерывания работы флота

Благодаря использованию поля `kid` (Key ID) в заголовке JWT-лицензии и массиву `cp_public_keys` в базе данных каждого экземпляра, ротация выполняется **в два шага без простоя**:

### Шаг 1: Генерация нового ключа в Vault Transit и экспорт публичной части
1. Создать новую версию ключа с новым идентификатором `kid`:
   ```bash
   vault write -f transit/keys/license-signer-2026-v2 type=ed25519
   ```
2. Экспортировать открытый ключ:
   ```bash
   vault read transit/keys/license-signer-2026-v2
   ```

### Шаг 2: Добавление нового публичного ключа во флот
1. Через Control Plane отправить обновление доверенных ключей во все экземпляры (инъекция в `instance_info.cp_public_keys`):
   ```json
   [
     {"kid": "license-signer-2026-v1", "public_key": "MCow...", "valid_until": "2026-12-31T23:59:59Z"},
     {"kid": "license-signer-2026-v2", "public_key": "MDsw...", "valid_until": "2027-12-31T23:59:59Z"}
   ]
   ```
2. Экземпляры теперь принимают лицензии, подписанные как старым, так и новым ключом.

### Шаг 3: Переключение генератора лицензий в Control Plane
1. В конфигурации Control Plane переключить активный ключ подписи:
   ```yaml
   dwh.control-plane.license.active-kid: "license-signer-2026-v2"
   ```
2. Все вновь выпускаемые лицензии и обновления подписываются новым ключом.

### Шаг 4: Вывод старого скомпрометированного ключа
1. После того как 100% активных экземпляров получили новые лицензии:
2. Удалить старый ключ из `cp_public_keys` экземпляров и отозвать его в Vault:
   ```bash
   vault delete transit/keys/license-signer-2026-v1
   ```

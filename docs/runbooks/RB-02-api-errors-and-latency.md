# RB-02: Ошибки и задержки API

**Версия:** 1.0

**Обновлено:** 2026-10-07

**Алерты:** `SmartupcmsApiErrorBudgetBurnFast`, `SmartupcmsApiLatencyP99High`
(critical); `SmartupcmsApiErrorBudgetBurnSlow`, `SmartupcmsApiLatencyP95High`,
`SmartupcmsEntityRuntimeLatencyHigh` (warning) — [SLO и алерты](../ops/slo.md).

## Сигнал и цель

- Сгорание бюджета: доля ответов 5xx на `/api/…` выше 14.4× (за 1 ч и 5 мин)
  или 6× (за 6 ч и 30 мин) от бюджета 0.1 % (SLO доступности 99.9 %).
- Задержка: p95 API или entity runtime выше 300 мс, p99 API выше 1 с 15 мин
  (пороги по умолчанию, `NFR-PERF-02`).

Цель — найти маршрут и причину, остановить расход бюджета.

## Немедленные действия

1. Был ли деплой за последний час? Если да и ошибки начались с ним —
   [откат](../ops/rollback.md) раньше глубокой диагностики.
2. Откройте дашборд «SmartupCMS: API and SLO»: панели «Requests by status» и
   «Slowest routes» показывают, какие `uri` дают 5xx или медленны.

## Диагностика

1. Ошибки по маршрутам:
   `sum by (uri, status, exception) (rate(http_server_requests_seconds_count{status=~"5.."}[5m]))`.
2. Журнал сервера за окно алерта: исключения, `57014` (statement timeout),
   разрывы соединений; ищите по `traceparent` запроса.
3. Насыщение: дашборд «database and disk» — пул занят, ожидание соединения
   ([RB-07](RB-07-database-pool-and-disk.md)); JVM heap и CPU на обзорном.
4. Зависимости: pg-dwh, Typesense, ClamAV, S3 (`smc_storage_operation_seconds`,
   `smc_file_scanner_seconds`) — их отказ деградирует одну функцию.
5. Для entity runtime: какая сущность (`uri` с `{code}` не различает коды —
   смотрите журнал), тяжёлые фильтры и сортировки без индекса.

## Восстановление

- Регрессия релиза — откат; дефект — исправление и релиз.
- Медленный запрос — индекс новой миграцией или исправление запроса; не
  поднимайте `SMC_DB_STATEMENT_TIMEOUT` вместо исправления.
- Перегрузка — снять источник (импорт, отчёт), добавить ресурсы.

## Эскалация и закрытие

Fast burn дольше 30 мин или p99 выше 1 с у основных экранов — эскалация
владельцу установки. Закрытие: доля ошибок и задержки вернулись в SLO, в
инциденте записаны расход бюджета и причина.

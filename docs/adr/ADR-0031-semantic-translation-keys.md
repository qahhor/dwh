# ADR-0031: Семантические ключи переводов

**Статус:** Принято (2026-10-01)
**Дата:** 2026-10-01
**Зависит от:** ADR-0020 (миграции и их правила), ADR-0021 (модель ошибок,
ключи `error.<модуль>.<имя>`), ADR-0023 (старые формы на один релиз — до
финального релиза не действует, раздел 5); план 10/10, пункт 4.5

---

## 1. Контекст

Русский каталог `apps/server/src/main/resources/i18n/ru.json` — источник
ключей, `uz` и `en` полные. Большую часть ключей экранов когда-то создал
генератор из русского текста: он транслитерировал фразу
(`tasks.soispolniteli`, `iam.kanaly_svyazi`), обрезал её на 48
символах посреди слова (`analytics.raspredelenie_..._po_i`), а одинаковые
фразы различал хэшем (`audit.tablica.6f39b76`). Такой ключ не говорит, где он
показан и что это за элемент, меняется вместе с текстом и не читается без
знания русского.

Состояние до решения (2679 ключей, подсчёт правилами из раздела 2.5):

| Категория | Ключей |
|---|---|
| Транслит в имени | 856 (+1 смешанный `iam.status_2fa`) |
| Обрезаны посреди фразы | 55 |
| С хэш-суффиксом | 9 |
| Переименовано всего | 857 |

Категории пересекаются: обрезанные и хэшированные ключи тоже транслитом.

## 2. Решение

### 2.1. Соглашение

Ключ — `<модуль>.<экран>.<элемент>` (при необходимости
`<модуль>.<экран>.<часть>.<элемент>`), каждый сегмент — английские слова в
snake_case, первый символ сегмента — буква.

- **Модуль** — первый сегмент, область, которой принадлежит экран; это тот же
  префикс, что объявляет контракт переводов фичи (`owns` в `*.i18n.spec.ts`):
  `tasks`, `projects`, `iam`, `settings`, `audit`, `files`, `announcements`,
  `analytics`, `system`, `notifications`, `auth`, `layout`, `upl`. Общие
  компоненты интерфейса — `ui.<компонент>.*`. Ошибки — по ADR-0021
  `error.<модуль>.<имя>`.
- **Экран** — страница, диалог или панель: `list`, `editor`, `detail`,
  `filter`, `table`, `kanban`, `dictionaries`, `dashboard`, `health`,
  `members`, `languages`; часть экрана — следующим сегментом
  (`iam.profile.tokens.*`, `iam.users.permissions.*`). Текст, общий для
  нескольких экранов модуля, — `<модуль>.common.<элемент>`.
- **Элемент** называет роль текста, а не пересказывает его: `title`,
  `subtitle`, `empty`, `empty_hint`, `load_failed`, `save_failed`,
  `<поле>_placeholder`, `<действие>_confirm`, `<поле>_hint`, тосты `created`,
  `updated`, `deleted`. Варианты одного слова различаются смыслом
  (`created_masculine` / `created_feminine`, `table` / `table_label`), а не
  хэшем.
- **Ключи из кода.** Ключ, который код собирает из значения, сохраняет
  написание кода в последнем сегменте: `upl.err.<CODE>`, `audit.event.I`,
  `projects.state.A`, `iam.users.state.P`, `nav.<код пункта меню>`. Префиксы
  перечислены в аудите (`CODE_KEY_PREFIXES`).
- **Число и существительное** (дополнение 2026-10-11). Текст, где число
  стоит перед словом, которое с ним согласуется («1 форма, 2 формы, 5 форм»),
  — группа форм множественного числа: `<ключ>.one`, `<ключ>.few`,
  `<ключ>.many`, `<ключ>.other` в каждом из каталогов ru, uz и en (uz и en
  повторяют текст там, где их правила формы не различают), в каждой форме —
  `{count}`, у самой группы своего текста нет. Код зовёт ключ группы с числом
  `count` (`'iam.roles.matrix.forms_count' | t: { count: n }`), форму выбирает
  `I18nService.translate` по `Intl.PluralRules` текущего языка. Другой выход —
  подпись перед числом («Найдено форм: {count}», «Строк в файле: {n}»); текст
  с двумя числами пишется только так. Ошибки сервера форм не выбирают и тоже
  пишутся подписью («Символов — не больше {max}»).

### 2.2. Переименование

- Карта старый → новый ключ — `apps/web/scripts/i18n-key-renames.json`
  (857 пар). Она же — вход миграции.
- Скрипт `apps/web/scripts/i18n-rename-keys.mjs` (`npm run i18n:rename`)
  применяет карту к каталогам ru/uz/en (порядок ключей сохраняется), к
  исходникам веба и спецификациям, к Java (основной код и тесты), e2e и
  скриптам репозитория, понимает и экранированную запись `iam\.users` в
  шаблонах PowerShell. `--check` падает, если старый ключ где-то остался,
  `--sql` печатает пары для миграции. Выпущенные миграции, сама карта и тесты
  миграций переименования не переписываются.
- Затронуты 147 файлов, на сервере — подписи истории записи
  (`MdUserHistorySources`, `MsTaskHistorySources`) и полей списка файлов
  (`MfFileQuery`), которые сервер отдаёт как `labelKey`. Веб и сервер
  поставляются вместе, поэтому старые подписи не сохраняются.
- **Ключи ошибок не переименованы**: среди них нет транслита. Они уходят
  клиентам как `messageKey`; если ключ ошибки когда-нибудь переименуют, старый
  ключ остаётся в каталогах на один релиз как псевдоним, а изменение
  помечается как видимое в API (ADR-0023). Переход `error.fnd.*` к модулям-владельцам
  (`error.jobs.*`, `error.warehouse.*`, `error.units.*`,
  `error.versioning.*`, `error.actor.*`) выполнен 2026-10-03 без псевдонимов:
  установок у клиентов нет (ADR-0030, раздел 6).

### 2.3. Переводы администратора

Миграция V156 переносит строки `md_i18n_translation_overrides` и ключи
названий `md_navigation_items.title_key` со старых ключей на новые:

1. значение копируется под новый ключ, затем строка под старым ключом
   удаляется — ни одно значение не теряется и не меняется;
2. если перевод есть и под старым, и под новым ключом, остаётся значение под
   новым ключом (его записали для нового каталога намеренно), старая строка
   удаляется;
3. язык, у которого изменился набор переводов, и изменённый пункт меню
   получают новую ревизию, чтобы открытый до обновления редактор перечитал
   данные, а не сохранил старые ключи обратно (ADR-0024).

Пары в миграции сгенерированы из карты; тест сверяет, что они совпадают.
Следующее переименование получает свою карту и свою миграцию: выпущенная
миграция не меняется.

### 2.4. Запрет в аудите

`npm run i18n:audit` (правила — `apps/web/scripts/i18n-key-rules.mjs`)
падает, если:

- сегмент ключа содержит слово, которое есть среди транслитерированных слов
  русского каталога и отсутствует в английском каталоге (**транслит**);
  исключения — короткий список имён и кодов (`WORD_ALLOWLIST`: `ne` —
  оператор фильтра, `stat`, `sha`, коды языков), у каждого причина;
- сегмент — хэш или кончается хэшем (6+ шестнадцатеричных знаков с цифрой и
  буквой) (**хэш**);
- элемент из трёх и более слов повторяет начало фразы (транслит русского
  значения или английский текст) и обрывается посреди слова, или длиннее 40
  знаков и обрывается на границе слова, или кончается на `_` (**обрезка**);
- новый ключ не следует соглашению 2.1; старые ключи вне соглашения (496,
  в основном двухсегментные `common.save`, `tasks.col_*`) перечислены в
  `apps/web/scripts/i18n-key-baseline.txt`, список только сокращается: ключ,
  который переименовали или привели к соглашению, аудит требует оттуда убрать;
- переименованный ключ снова появился в каталогах или коде.

Перед проверкой аудит прогоняет правила на известных плохих и хороших
образцах (`SELF_CHECK`) и падает, если вердикт изменился.

### 2.5. Генератор модулей

CLI `cms` (`tools/cms-cli`, план 10/10, пункт 6.1; до 2026-10-03 —
`scripts/dev/create-module.ps1`) создаёт ключи по соглашению: подписи
`<код сущности>.col.<поле>`, варианты выбора `<код сущности>.<поле>.<вариант>`,
названия прав `<код сущности>.rights.*`, пункт меню `nav.<область>_<сущность>`.

## 3. Проверки

- `npm run i18n:audit` — 0 транслитерированных, хэшированных и обрезанных
  ключей, новые ключи по соглашению, самопроверка на образцах.
- `npm run i18n:audit` — группа форм полная во всех трёх каталогах и в
  каждой форме есть `{count}`; число, приклеенное к согласуемому русскому
  слову (`{count} форм`), — ошибка (предлоги, сокращения с точкой и единицы
  вроде «МБ», «с» не согласуются и пропускаются).
- `npm run i18n:rename -- --check` — ни один старый ключ не остался.
- `I18nKeysMigrationTest` — база до V156 с переводами администратора на
  старых ключах (в том числе под обоими ключами) и пунктом меню; после
  миграции значения под новыми ключами, старых ключей нет, ревизии сдвинуты
  только там, где были изменения, пары миграции совпадают с картой.
- Контракты переводов фич (`*.i18n.spec.ts`) и все спецификации веба,
  `ErrorTextsTest`, `CatalogProblemMessagesTest`, `MdI18n*`.

## 4. Последствия

- Новый текст получает ключ по месту показа; переименование текста ключ не
  меняет.
- Администратор, который переопределил перевод, видит его под новым ключом;
  импортированный словарь со старыми ключами редактор отклонит как словарь с
  неизвестными ключами.
- 496 старых ключей вне соглашения переименовываются тем же скриптом с новой
  картой и новой миграцией, когда их экран меняется.
- Качество английских текстов не менялось: часть значений `en.json` —
  машинный перевод; это отдельная работа над каталогом, а не над ключами.

## 5. Отмена переходного периода (2026-10-01): установок у клиентов нет

Владелец продукта решил 2026-10-01: до финального релиза установок у клиентов
нет (`AGENTS.md`, §3), поэтому переходные меры этого решения до финального
релиза не применяются:

- Переименованный ключ не остаётся в каталогах псевдонимом: старый ключ
  удаляется сразу, изменение записывается в `CHANGELOG.md` (для ключей, видимых
  в API, — как ломающее, ADR-0023). Как это применяется к ключам ошибок —
  раздел 2.2.
- Следующие переименования (496 ключей из базового списка, раздел 4) идут
  картой и скриптом, но без миграции переводов администратора: переносить
  нечего. Выпущенная V156 и `I18nKeysMigrationTest` остаются как есть
  (выпущенные миграции не меняются).
- Импортированный словарь со старыми ключами отклоняется, как сказано в
  разделе 4; переходного приёма старых ключей нет.

После финального релиза переименование ключа снова требует миграции
переводов администратора и, для ключей в API, механизма устаревания
ADR-0023 (раздел 2, пункт 5).

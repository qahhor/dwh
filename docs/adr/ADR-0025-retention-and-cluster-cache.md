# ADR-0025: Сроки хранения журналов и кэш в кластере

**Статус:** Принято (2026-09-30)
**Дата:** 2026-09-30
**Зависит от:** ADR-0020 (именование и миграции); план 10/10, пункт 3.13

---

## 1. Контекст

Журнальные таблицы (события безопасности, попытки входа, коды, закрытые
сессии, журнал и очередь вебхуков, входящие уведомления и их очередь, запуски
фоновых заданий) росли без предела: очищались только ключи идемпотентности,
выгрузки и — через архив — журнал аудита. Справочники (статусы и типы задач,
модули, меню, доп. поля) кэшировались на узле на 10 минут: после правки второй
узел до 10 минут отдавал старое. Словари i18n уже сверяют ревизию языка при
каждом чтении и между узлами согласованы.

## 2. Решение

1. **Срок хранения объявляет модуль.** Бин `RetentionPolicy` (`common.retention`):
   имя, таблица, условие устаревшей строки с `:cutoff`, срок по умолчанию.
   Десять правил в модулях audit, kauth, kwh, ms.notify, fnd. Срок меняется
   настройкой `smc.retention.days.<имя>`; 0 — хранить всегда. Строки «в
   работе» (очередь в ожидании, открытая сессия, выполняющееся задание) не
   удаляются никогда — условие отбирает только конечные.
2. **Задание очистки** (`RetentionJob`, ночью): партии по 5000 строк
   `delete … where ctid = any(array(select ctid … limit … for update skip locked))`,
   каждая — отдельный короткий оператор; не больше 200 партий на таблицу за
   проход. Два узла не мешают друг другу. Индексы под условия — V136, V137.
3. **Кэш сообщает кластеру.** `ClusterCacheManager` оборачивает кэши узла:
   чтение и запись локальны; очистка применяется сразу, повторно после
   коммита и после коммита уходит `NOTIFY smc_cache '<узел> <кэш>'`.
   Откаченная транзакция не сообщает ничего. `CacheInvalidations` на каждом
   узле держит своё соединение с `LISTEN smc_cache` и очищает названный кэш;
   собственные сообщения узел пропускает. После потери соединения узел
   очищает все кэши (мог пропустить сообщение) и слушает снова.

## 3. Проверки

- `RetentionJobIntegrationTest`: старые строки всех десяти журналов уходят,
  свежие и «в работе» остаются; пять циклов старых строк не увеличивают
  таблицы; повторный проход ничего не удаляет.
- `ClusterCacheIntegrationTest`: изменение на одном узле очищает кэш второго
  не позже чем через 2 с после коммита — и через `@CacheEvict` сервиса;
  откат не сообщает ничего; эха нет.

## 4. Последствия

- Каждый узел занимает одно соединение пула под `LISTEN`.
- Журнал загрузок `fnd_load_log` не очищается: это история того, что попало в
  хранилище. Журнал аудита уходит только через проверенный архив.
- Сроки по умолчанию — предположение (год для событий безопасности, месяц для
  попыток входа и отправленной очереди, полгода для входящих); их сдвигают
  настройкой без изменения кода.

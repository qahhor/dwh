# ADR-0039: графики, подготовленные наборы данных и помощник черновиков

**Статус:** принято; STU-06 реализован и проверен локально 2026-10-16. Приёмка целевого контура и реального LLM-провайдера остаётся отдельным гейтом.

## Решение

Сохраняются модульный монолит, EntityReports/QueryAggregate, сохранённые отчёты, панели, simple-form v1, CLI/Flyway и серверные права. Новых зависимостей нет.

1. Дополнительные charts: line (одна DATE/INSTANT группировка с bucket, одна мера, UTC, разрывы для NULL и отсутствующих периодов) и horizontalBar (одна категориальная группировка, одна мера, ось нуля и отрицательные значения). Исходная таблица доступна всегда. Неполный результат, неоднозначная валюта/размерность или некорректное число дают таблицу с объяснением; повторной агрегации средних нет.
2. Dataset — именованная read-only проекция root entity, объявленная доверенным кодом. Один объявленный REF N:1, grain — одна root-запись. LEFT JOIN scoped/partitioned/non-archived target сохраняет root-строки. Недоступная по scope, отсутствующая или архивная target-запись даёт NULL. Отсутствие target.view закрывает весь dataset и metadata.
3. Target-проекции ограничены SELECT/BOOL/DATE/INSTANT; nullable, несортируемые. Проверяются root REF ACL и ACL каждого target-поля. Первый dataset ms.tasks.projects выбран владельцем: projectId → ms.projects; проекции projectCreatedAt и projectModifiedAt, мера count считает задачи. Группировка по проекту и приоритету остаётся корневой. Задача без проекта сохраняется с NULL проекциями. Коллекции и пользовательские SQL/joins не разрешены; новых полей в доменной модели нет. Модуль задач по-прежнему отключаемый.
4. Optional dataset входит в запрос и сохранённый report state. Маршруты entity, listCode и widget.entityCode сохраняются. Общий resolver используется при metadata/run/save/catalog/panel/XLSX; экспорт получает metadata того же источника. Права и module flags проверяются заново. Поле периода панели разрешается в каноническом dataset сохранённого отчёта, включая доступные DATE/INSTANT проекции. Прежние лимиты: 2 группировки/4 меры/1000 групп/5 секунд SQL.
5. LlmProvider — дополнительный SPI; транспорт использует явно настроенный OpenAI-compatible Chat Completions endpoint через JDK HttpClient. Это позволяет подключить облачный или собственный gateway без новой библиотеки. Совместимость конкретной модели — отдельная приёмка. Endpoint/model задаются оператором; HTTPS обязателен вне локальной тестовой фикстуры, redirects запрещены. Default disabled, без автоматического выбора провайдера; владелец подтвердил подключаемый шлюз и запрет реальной отправки наружу на текущем этапе.
6. Помощник предлагает только simple-form v1. Передаются пользовательское задание (до 2000 Unicode code points) и фиксированное описание формата; существующие записи, схемы клиента, файлы и секреты автоматически не добавляются. Ответ до 32 KiB проходит существующий строгий validator. Возвращается декларация без пакета/активации. Structured output не заменяет локальную проверку.
7. Право studio.forms.assist плюс md.settings.update, активный studio и feature flag проверяются до вызова и после ответа. Prompt/response не сохраняются и не журналируются; ошибки sanitised, cache/replay запрещены. До 2 конкурентных запросов на процесс, timeout 30 секунд, без автоматических повторов. Бюджет/retention поставщика настраивает оператор до включения.
8. UI показывает предложение отдельно. Явное применение с подтверждением замены несохранённого ввода сбрасывает пакет и выбирает CLI. Сохранение, подготовка и активация остаются отдельными действиями. Отмена/смена контекста/новый запрос инвалидируют поздний ответ.

## Приёмка и эксплуатация

ACC-22: charts NULL/zero/negative/gaps/UTC/currency/truncation, доступная таблица и общий renderer панелей.
ACC-23: dataset JSON/XLSX golden, root grain, scoped/archived target, ACL/module revocation во всех путях, запрет произвольного SQL, bounded EXPLAIN.
ACC-24: disabled/forbidden/timeout/busy/invalid output, локальная HTTP fixture транспорта, повторная авторизация, отсутствие записи/активации и stale UI response.
ACC-19: keyboard, 360/1440 px, обе темы, Axe; stub browser отделён от live/staging.

Откат кода с новыми сохранёнными chart/dataset значениями требует проверки потребителей; автоматического преобразования нет. Секрет задаётся только окружением/secret store. До реального включения нужны выбор модели, согласование контекста/retention/бюджета и целевой smoke без клиентских данных. Локальная fixture этого не заменяет; отправка наружу и расходы сейчас не разрешены.

Контракт транспорта: [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Строгая локальная валидация обязательна независимо от провайдера.

## Уточнение 2026-10-19: наборы данных администратора (ADR-0044)

Наряду с наборами, объявленными в коде, администратор задаёт наборы без выпуска (`md_report_datasets`, права
`md.report_datasets`): источник — сущность или живая форма, необязательно на уровне строк документа, выбранные поля,
постоянный фильтр DSL и вычисляемые показатели — формулы над агрегатами. Отчёт называет такой набор `ds.<код>`; общий
`EntityReportDatasets.resolve` обслуживает оба вида во всех путях (метаданные, запуск, сохранение, каталог, панель,
XLSX). Гарантии этого ADR сохраняются: набор не расширяет область данных и права на поля читателя, SQL из
пользовательского текста нет. Подробности — [ADR-0044](ADR-0044-report-analytics.md).

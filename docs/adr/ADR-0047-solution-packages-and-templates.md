# ADR-0047: пакеты решений и шаблоны

**Статус:** принято 2026-10-19 (этап 3, шаг 3.2 плана конструктора форм и отчётов); реализовано в `main` 2026-10-19.
**Основание:** план 10/10, раздел «Конструктор форм и отчётов», этап 3 — «перенос пакетов и шаблоны» с критерием
успеха этапа «шаблон формы разворачивается у нового клиента за день»; [ADR-0041](ADR-0041-live-form-evolution.md)
(живые формы и их версии, эталоны «Визит торгового представителя», «Заявка клиента», отчёт «по регионам»),
[ADR-0043](ADR-0043-live-form-documents.md) (эталон «Заказ со строками и согласованием»).
**Зависит от:** [ADR-0020](ADR-0020-database-naming.md), [ADR-0024](ADR-0024-optimistic-locking.md),
[ADR-0025](ADR-0025-retention-and-cluster-cache.md), [ADR-0035](ADR-0035-declaration-lifecycle.md) (пакет и доверие),
[ADR-0038](ADR-0038-live-simple-forms.md) (simple-form-package, активация, лимит 100 форм), ADR-0041 (совместимые
изменения), [ADR-0044](ADR-0044-report-analytics.md) (наборы данных), [ADR-0045](ADR-0045-report-mailings.md)
(рассылки), [ADR-0046](ADR-0046-live-form-automations.md) (автоматизации).

## Контекст

Решение, собранное администратором в Studio — живые формы со строками, нумерацией, статусами, файлами, формулами и
раскладкой, справочники, наборы данных, отчёты, рассылки и автоматизации, — живёт в одной установке. Чтобы развернуть
то же у нового клиента, его пришлось бы собрать руками заново. Нужен переносимый пакет решения и готовые шаблоны, при
этом пакет не должен переносить данные и учётные записи установки, выдавать права сам по себе или запускать
автоматизации без проверки человеком.

Что уже есть. ADR-0035 вводит «пакет» как неизменяемый артефакт одной формы с контрольной суммой; ADR-0038 —
`simple-form-package` v1 (`formatVersion`, `kind`, `declaration`, `checksum`), который сервер проверяет заново при
активации (`StudioPackages`, `MdSimpleFormDeclarations.prepare`: строгий разбор, SHA-256 канонического JSON). Пакет
решения **переиспользует** его для каждой формы: формы внутри пакета решения — это те же simple-form-package, проверяемые
тем же кодом, а не второй формат деклараций.

| Вариант доверия | Почему нет / да |
|---|---|
| Подпись пакета ключом выпуска (как образы и bundle в ADR-0040: Cosign, GitHub provenance) | Подпись ADR-0040 удостоверяет сборку CI, а не пакет, выгруженный администратором в рантайме; ключ подписи в каждой установке — новое хранилище секретов, ротация и отзыв; подпись не заменяет проверку содержимого |
| **Контрольная сумма + полная повторная проверка каждой части путями её создания; доверие — решение администратора, загружающего файл** | **Выбран**: сумма ловит порчу и правку файла после выгрузки, а «кто автор» решает администратор с правом импорта; шаблоны доверенные, потому что поставляются в самом приложении |

| Вариант применения | Почему нет / да |
|---|---|
| Свой валидатор пакета, повторяющий проверки форм, справочников, отчётов, рассылок, автоматизаций | Две реализации правил, которые разойдутся |
| **Проверка = применение тех же шагов в транзакции, которая всегда откатывается; применение = те же шаги в транзакции, которая фиксируется, только если нет отказов** | **Выбран**: предпросмотр показывает ровно то, что сделает применение, с причинами отказа из тех же правил |

## Решение

### 1. Формат пакета (`solution-package` v1)

- JSON: `formatVersion` 1, `kind` `solution-package`, `code` (`[a-z][a-z0-9-]{1,39}`), `version` (три числа),
  `title` и необязательное `description` (ru/uz/en), `requires.simpleFormFormat` (новейший формат simple-form его
  форм), `producedBy` (версия приложения), `placeholders`, `lists`, `forms`, `datasets`, `reports`, `mailings`,
  `automations`, `grants`, `checksum`. Схема — `SolutionPackage` в `docs/api/openapi.json`.
- `checksum` — SHA-256 канонического JSON пакета без самой суммы (ключи объектов по алфавиту, порядок массивов
  сохраняется) — тот же способ, что у simple-form-package. Сумма считается по дереву, прочитанному из текста пакета,
  поэтому форматирование файла и порядок ключей её не меняют.
- Формы — массив simple-form-package v1: активная декларация формы со строками, нумерацией, статусами, файлами,
  формулами и раскладкой; форма идёт после форм, на которые ссылается.
- Справочники — код, название, значения (по выбору при выгрузке — без значений). Наборы данных — как запрос
  `ReportDatasetRequest`. Отчёты — ключ, название, список, состояние (как его хранит отчёт), роли доступа. Рассылки —
  ключ, отчёт пакета, расписание, условие, параметры, каналы, получатели. Автоматизации — ключ, форма, триггер, условие,
  действия, часовой пояс. `grants` — права форм пакета, которые держала роль.
- Записей нет: пакет переносит решение, а не данные (образцы записей — не в этом шаге). Нет и id пользователей, ролей,
  подразделений, секретов, подписок на вебхуки (это интеграции установки с адресом и секретом — не переносятся).
- Границы: файл до 2 МиБ, глубина вложенности до 16; форм до 20, справочников до 50 (значений — до 500 на справочник),
  наборов данных до 20, отчётов до 50, рассылок до 20, автоматизаций до 50, подстановок до 50, ролей с правами до 20.

### 2. Подстановки вместо ссылок установки

- Роль установки становится подстановкой `role-<n>` с названием роли; фиксированные получатели рассылки и уведомления
  автоматизации — подстановкой пользователей с названием «Получатели рассылки «…»» (ru/uz/en из каталога), без имён и id
  людей. Подстановка `required`, если без неё элемент не сохранится (получатели рассылки; получатели уведомления, у
  которого нет других получателей).
- Автор автоматизации и владелец отчёта/рассылки не переносятся: владельцем становится импортирующий, автором
  автоматизации — тот, кто её включит (ADR-0046, п. 5).
- Значение, которое называет запись установки (фильтр отчёта или набора, умолчание параметра, значение параметра
  рассылки на поле-ссылке на запись, пользователя или подразделение), в пакет не попадает: выгрузка отказывает 422
  `error.studio.solution_record_values` с адресом. Коды значений справочников и вариантов выбора переносятся как есть.

### 3. Выгрузка

- Администратор выбирает формы и, по желанию, наборы данных, отчёты, рассылки, автоматизации. Сервер добавляет
  зависимости: отчёт рассылки; набор данных и форму отчёта; форму набора; форму автоматизации, формы, которые
  создают её действия, и формы прав её получателей; формы, на которые ссылаются поля и колонки форм; справочники всех
  форм. Сущности, объявленные в коде, есть в каждой установке и не добавляются.
- «Показать состав» (`POST /api/v1/studio/packages/export/preview`) возвращает, что войдёт и почему (`selected`,
  `dependency` с указанием, кому нужно), что ещё использует формы пакета (`related`: наборы данных, отчёты, рассылки,
  автоматизации — их можно добавить) и подстановки. Скачивание (`POST …/export`) — файл с суммой.
- Каждая часть читается тем путём и с тем правом, каким её читает собственный экран (декларация — право публикатора,
  справочник — `studio.lists.view`, набор — `md.report_datasets.view`, отчёт — каталог читателя, рассылка —
  `report.mailings`, автоматизация — `studio.automations.view`); права ролей — из матрицы, кроме административных ролей.

### 4. Загрузка и проверка

- `POST /api/v1/studio/packages/imports` (тело — файл пакета; необязательный `suffix`) проверяет по порядку: размер,
  UTF-8, глубину, дубликаты ключей, хвост → сумму (422 `error.studio.solution_checksum`) → формат (422
  `error.studio.solution_format`) → что пакет требует от установки (`requires.simpleFormFormat` выше читаемого — 422
  `error.studio.solution_newer`) → структуру со строгим разбором (неизвестные ключи, типы) → каждую форму как
  simple-form-package (сумма декларации, пространство `studio`, зарезервированные коды) → ссылки между частями
  (рассылка — на отчёт пакета, подстановка нужного вида, права — только форм пакета) (422 `error.studio.solution_invalid`
  с адресом части).
- Затем пакет **применяется в транзакции, которая всегда откатывается**, и каждый элемент получает исход: `create`,
  `upgrade` (новая версия формы по правилам совместимости ADR-0041; недостающие значения и новые названия справочника;
  изменённый набор данных, отчёт, рассылка, автоматизация), `unchanged`, `skip` (необязательная подстановка не
  сопоставлена) или `refused` с причинами — ключами каталога из тех же проверок (лимит 100 активных форм, код
  объявленной сущности, несовместимое изменение по каждому полю, права импортирующего и т. д.). Элемент исполняется в
  своей точке сохранения: отказ одного не прячет причины остальных. Сохраняется только загрузка с исходами (201 +
  `Location`); в установке ничего не меняется.
- Суффикс (`_` и до 5 строчных латинских букв или цифр) создаёт вторую копию решения: он добавляется к кодам форм,
  справочников и наборов пакета и ко всем ссылкам на них; формы готовятся заново, поэтому их суммы — суммы сервера.
- Права: загрузка и применение — `studio.packages.import`; каждый элемент дополнительно требует права своего вида
  (`studio.lists.manage`, `studio.forms.publish`, `md.report_datasets.manage`, `md.profile.update` и для доступа ролям
  `md.settings.update`, `report.mailings`, `studio.automations.manage`, для прав роли `md.roles.grant`) — без него
  элемент отказан с причиной. Пакет не расширяет прав импортирующего.

### 5. Сопоставление и применение

- `POST /api/v1/studio/packages/imports/{id}/apply` с `mapping`: роль — одна активная роль, пользователи — от 1 до 50
  активных пользователей; ключ, которого нет в пакете, и не сопоставленная обязательная подстановка — 422
  `error.studio.solution_mapping_invalid` с адресом. `dryRun` — та же проверка с сопоставлением, без изменений.
- Применение — те же шаги в одной транзакции: формы и справочники, затем (каталог и права импортирующего перечитываются
  в транзакции: новые формы и их права существуют только в ней) права ролей, наборы, отчёты, рассылки, автоматизации.
  Если отказан хоть один элемент — откат всего, 422 `error.studio.solution_refused`, загрузка хранит исходы с причинами.
  Иначе загрузка становится `applied` (кто, когда, с каким сопоставлением), аудит `studio_package_imports`; каждое
  изменение аудирует и собственный путь элемента. Повторное применение той же загрузки — 409.
- **Безопасность.** Рассылки и автоматизации создаются и при изменении пакетом снова становятся **приостановленными**:
  включает их администратор после проверки, и автоматизация исполняется от его имени. Права выдаются только роли, на
  которую администратор сопоставил подстановку, только права форм пакета и только импортирующим с правом выдачи прав;
  без сопоставления прав нет. Пакет не несёт кода: применяются только декларативные пути (декларации, справочники,
  наборы, отчёты, рассылки, автоматизации через их сервисы).
- **Идемпотентность.** Формы, справочники и наборы данных находятся по коду; отчёты, рассылки и автоматизации — по коду
  пакета (с суффиксом) и ключу элемента в `studio_package_objects` с суммой элемента. Повторная загрузка того же пакета
  даёт `unchanged` для всех элементов, и применение ничего не создаёт; изменённый элемент — `upgrade`; удалённый в
  установке объект создаётся заново. Включённая администратором автоматизация, которую пакет не менял, остаётся
  включённой. Другое сопоставление при повторном применении получателей уже созданных рассылок не меняет — их меняют в
  рассылке.

### 6. Шаблоны

- Шаблоны — пакеты в ресурсах приложения (`studio/templates/*.json`), читаются и проверяются как загрузка при каждом
  обращении: «Визит торгового представителя», «Заявка клиента», «Заказ со строками и согласованием» (строки товаров,
  номер, согласование, отчёт «Заказы по регионам» с еженедельной рассылкой, автоматизация согласования: дата отправки
  на согласование и уведомление согласующим), каждый с описанием на ru/uz/en и подстановками ролей («Торговый
  представитель», «Согласующий», «Оператор заявок») и получателей рассылки.
- «Создать из шаблона» (`POST /api/v1/studio/templates/{code}/imports`) — загрузка пакета шаблона; дальше то же
  сопоставление и применение. Общие части шаблонов (форма «Клиенты», справочник «Регионы») одинаковы, поэтому второй
  шаблон находит их `unchanged`.
- Тесты не дают шаблонам устареть: `SolutionTemplateFilesTest` читает каждый шаблон как загрузку (суммы форм и пакета,
  тексты ru/uz/en; `-Dtemplates.update=true` пересчитывает суммы после правки), `StudioPackageHttpTest` применяет каждый
  в установку и проверяет исходы.

### 7. Хранение

- V237: `studio_package_imports` (код, версия, название, сумма, источник `upload`/`template`, суффикс, проверенный
  пакет, исходы элементов, статус `preview`/`applied`, сопоставление, кто и когда загрузил, проверил, применил) и
  `studio_package_objects` (код пакета с суффиксом, вид, ключ, id объекта, сумма элемента, загрузка; уникально по коду,
  виду и ключу). V238: права `studio.packages` `export`/`import` для `chief_admin` и `admin`.
- Хранение: непримененная проверка удаляется через 30 дней (`package-previews`,
  `smc.retention.days.package-previews`); применённая загрузка — история установки.

### 8. API и веб

- `/api/v1/studio/packages`: `export/preview`, `export`, `imports` (загрузка, страница истории), `imports/{id}`,
  `imports/{id}/apply`; `/api/v1/studio/templates` (галерея, «создать из шаблона»). Операции Studio без ключа
  идемпотентности (`@NoIdempotency`, ADR-0035): повтор безопасен состоянием загрузки.
- Веб: «Пакеты и шаблоны» (`/settings/form-studio/packages`, из настроек и «Моих форм»): галерея шаблонов, загрузка
  файла с суффиксом, мастер выгрузки (выбор форм, состав с причинами, добавление связанного, скачивание), история;
  страница загрузки (`…/packages/imports/:id`): исходы с причинами и заметками, сопоставление ролей (выбор роли) и
  пользователей (выбор пользователей), «Проверить сопоставление», «Применить пакет» с подтверждением.
- CLI `cms` — генератор кода в репозитории без HTTP-клиента; перенос пакета между установками — это API выше
  (пример — рецепт cookbook «Перенести решение / создать из шаблона»), отдельная команда CLI не добавлялась.

## Последствия

- Готовое решение разворачивается у нового клиента загрузкой файла или из шаблона: проверка, сопоставление ролей и
  получателей, применение — без сборки руками.
- Пакет — та же проверка, что ручное создание: ничего, что администратор не может сделать сам, пакет не сделает.
- Ограничения: записи и образцы данных не переносятся; формулы автоматизаций и условия переносятся как текст — число,
  написанное в формуле как id пользователя, не распознаётся; подписи нет (доверие — решение импортирующего); получатели
  уже созданной рассылки при повторном применении не меняются; мастер выгрузки выбирает до 20 форм; страницу пакетов
  открывает право импорта (выгрузка — вкладка для права выгрузки).

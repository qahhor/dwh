# ADR-0005: Готовность платформы к AI/ML

**Статус:** Принято (CEO, 2026-08-27)
**Дата:** 2026-08-27
**Зависит от:** ADR-0002 (стек), ADR-0004 (экземпляр на клиента)

> **Совместимость идентификаторов (2026-09-03).** Упомянутые ниже рабочие
> обозначения `ТЗ-01` и `ТЗ-02` являются историческими и не заменяют
> [каноническое ТЗ](../technical-specification.md). Требования к API-токенам,
> серверной авторизации и аудиту теперь трассируются как `FR-AUTH-03`,
> `FR-AUTH-04`, `FR-IAM-05`, `FR-WORK-04` и `FR-ADMIN-02`. Для
> `Idempotency-Key`, pgvector и ML-витрин утверждённой замены среди `FR-*`,
> `NFR-*` и `AC-*` пока нет.

---

## 1. Контекст

CEO обозначил три перспективных AI/ML-направления:

1. **Прогнозная аналитика на DWH** — прогноз продаж, OOS, churn, аномалии (классический ML).
2. **LLM-ассистент в продукте** — «спроси свои данные», генерация сводок/отчётов, помощник в UI.
3. **AI-агенты** — автоматизация действий в системе через наш API.

Ничего из этого не строится в Этапе 1. Задача этого ADR — зафиксировать **принципы, которые
делают эти сценарии дешёвыми потом и почти бесплатными сейчас**, и явно назвать то, чего мы
НЕ делаем заранее.

## 2. Решения (принципы)

### П1. Ядро остаётся на Java; ML/AI — отдельные сервисы

Java-ядро не обрастает ML-кодом. Модели и LLM-оркестрация живут в отдельных сервисах
(Python-экосистема: FastAPI + ML-стек, либо Spring AI/LangChain4j для LLM-шлюза, выбор —
при реализации), общаются с ядром по REST через тот же API и RBAC, что и люди.
В single-tenant модели (ADR-0004) ML-сервис — просто ещё один контейнер в compose экземпляра.

### П2. DWH (Этап 2) — единственный источник обучающих данных и фич

Не строим отдельных «ML-выгрузок» из OLTP. Фичи, витрины для обучения и скоринга — слой marts
DWH. Это уже запланировано; AI-требование лишь подтверждает приоритет Этапа 2.

### П3. API проектируется machine-friendly с первого дня (для будущих агентов)

Это единственный пункт, влияющий на Этап 1 напрямую:
- полный OpenAPI из кода (уже в ТЗ, NFR-10);
- **агент = обычный пользователь**: API-токен, права через RBAC, никаких «служебных обходов»;
- мутирующие эндпоинты идемпотентны (заголовок `Idempotency-Key` на POST);
- действия по токену пишутся в аудит с признаком «через API» — действия агентов различимы;
- ошибки структурные (RFC 9457) — агент может реагировать программно.

### П4. pgvector — штатное расширение нашего PostgreSQL 18

Эмбеддинги и семантический поиск (база LLM-ассистента, RAG по данным клиента) — в том же
PostgreSQL через `pgvector`. Отдельную векторную СУБД не вводим, пока объёмы не заставят.
В Этапе 1 расширение просто включено в образ БД (нулевая стоимость).

### П5. События как сырьё для ML

Дисциплина, уже заложенная в ТЗ, объявляется контрактом: `audit_log` (кто/что/когда, JSONB) и
события notification-сервиса — это будущие обучающие последовательности. Правило: новая
бизнес-фича обязана порождать события через эти механизмы, а не молча менять строки.

### П6. LLM-провайдеры — за шлюзом

Когда появится LLM-ассистент: один внутренний шлюз (интерфейс `LlmProvider`), провайдеры
(облачный API / self-hosted модель) — конфигурация экземпляра. Данные клиента не покидают
экземпляр без явной настройки — в single-tenant модели это простое и продаваемое обещание.

## 3. Чего сознательно НЕ делаем сейчас

| Не делаем | Почему |
|---|---|
| Kafka/стриминг «на будущее» | Очередь в PostgreSQL покрывает текущие объёмы (ТЗ NFR); брокер — когда появится реальный поток |
| Feature store, MLOps-платформа | Нет ни одной модели; преждевременно |
| Выбор конкретного LLM-провайдера/модели | Рынок меняется быстрее наших этапов; решение — при реализации ассистента |
| GPU-инфраструктура | Классический ML на DWH живёт на CPU; GPU — только под self-hosted LLM, если он вообще понадобится |

## 4. Последствия

- В Этап 1 добавляются: `Idempotency-Key` на мутирующих POST, признак «через API-токен» в аудите,
  pgvector в образе PostgreSQL. Всё остальное — уже в ТЗ.
- Этап 2 (DWH) становится ещё важнее: это пререквизит всех трёх AI-направлений.
- AI-сценарии реализуются без переделки ядра: новые сервисы + существующий API.

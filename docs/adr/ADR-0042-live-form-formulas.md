# ADR-0042: язык формул живых форм

**Статус:** принято 2026-10-18 и реализовано в этапе 2, шаг 2.1 плана универсального конструктора (раздел
«Конструктор форм и отчётов» в [плане 10/10](../plan-10-10.md)). Дополняет [ADR-0041](ADR-0041-live-form-evolution.md)
(формат simple-form 5) и [ADR-0038](ADR-0038-live-simple-forms.md); их гарантии сохраняются: без DDL в runtime, граница
`form_id`, права, аудит, отказ одной формы не роняет каталог.

## Контекст

Этап 1 дал администратору форму со ссылками, областью данных и раскладкой, но без логики: сумма заказа, дата по
умолчанию «сегодня», поле, видимое и обязательное по условию, правило «скидка не больше 30 %» требовали кода. Платформа
уже умеет часть этого в объявлении сущности (ADR-0032): `FieldCondition` (только `eq/ne/in/empty` по выбору, ссылке и
флагу), `FieldReadonly.WHEN`, вычисляемое поле через SQL-выражение (`FieldSource.Computed`), межполевые правила
`EntityRule` (код на Java). Для администратора без разработчика этого мало: условия не умеют сравнивать числа и даты,
вычисляемое поле — это SQL, правило — это класс. Нужен язык выражений, который безопасно хранится в декларации живой
формы и одинаково вычисляется на сервере и в браузере.

## Рассмотренные варианты

| Вариант | Суть | Почему не выбран / выбран |
|---|---|---|
| A. SQL-фрагменты | формула — выражение PostgreSQL в запросе | исполнение произвольного SQL из данных администратора, инъекции, зависимость от схемы `payload`; противоречит ADR-0038 — **не выбран** |
| B. Встроенный движок сценариев (JavaScript/SpEL/MVEL) | готовый интерпретатор на сервере и в вебе | рефлексия и доступ к классам, неограниченные циклы и рекурсия, разные семантики Java и JS, тяжёлые зависимости — **не выбран** |
| C. Расширить `FieldCondition` | новые операторы в DSL условий ADR-0032 | `FieldCondition`, `FormFlags` — STABLE-контракт Platform API (japicmp), арифметики и функций в DSL нет — **не выбран** |
| D. Свой маленький язык | лексер, парсер, проверка типов и интерпретатор на сервере; браузер интерпретирует проверенное дерево | полный контроль над границами и семантикой, одна грамматика; цена — своя реализация и общий набор тестов — **выбран** |

Для общей семантики сервера и веба рассмотрены: (1) два парсера и два интерпретатора; (2) парсер и проверка только на
сервере, браузеру отдаётся проверенное дерево (AST) и интерпретатор на TypeScript; (3) WebAssembly-сборка серверного
интерпретатора. Выбран (2): парсер и проверка типов — одни (сервер), дерево отдаётся в `form-meta`, интерпретаторы на
Java и TypeScript проверяются общим набором случаев (`docs/api/formula-conformance.json`); (1) удваивает грамматику и
сообщения об ошибках, (3) тянет сборочную цепочку и размер бандла.

## Решение

1. **Язык** (`com.smartup24.cms.instance.common.formula`): выражения без циклов, присваиваний, рекурсии, SQL и
   рефлексии.

   ```
   expression := or
   or         := and ("or" and)*
   and        := not ("and" not)*
   not        := "not" not | comparison
   comparison := concat (("=" | "!=" | "<>" | "<" | "<=" | ">" | ">=") concat)?   — без цепочек
   concat     := additive ("&" additive)*
   additive   := term (("+" | "-") term)*
   term       := unary (("*" | "/") unary)*
   unary      := "-" unary | primary
   primary    := число | текст в "…" или '…' | true | false | null | поле | функция(аргументы) | (expression)
   ```

   Типографские `× ÷ − ≠ ≤ ≥` читаются как `* / - != <= >=`. Поле — по ключу (`qty`); ключевые слова уже
   зарезервированы как идентификаторы полей.
2. **Типы:** `number` (точная десятичная), `text`, `bool`, `date`, `datetime` (момент, до секунды), `time`, `option`
   (код выбора или значения справочника, сравнивается с текстом), `ref` (ключ записи формы или пользователя,
   сравнивается с числом), `null`. Тип каждого узла проверяется при проверке формулы: арифметика — числа, `&` склеивает
   любые значения как текст, `=`/`!=` — один тип (текст с кодом, ключ с числом), порядок — числа, тексты, даты, моменты
   и время, `and/or/not` — да/нет.
3. **Функции (25):** `round(x[, n])`, `abs`, `min`, `max`, `if(условие, то, иначе)`, `coalesce`, `isEmpty`, `len`,
   `upper`, `lower`, `trim`, `contains`, `today()`, `now()`, `date(г, м, д)`, `year`, `month`, `day`, `weekday`
   (понедельник = 1), `hour`, `minute`, `dateOf(момент)`, `addDays`, `addMonths` (конец месяца прижимается),
   `daysBetween(a, b)` (b − a). `today()`, части момента и `dateOf` — в часовом поясе запроса.
4. **Числа:** `BigDecimal` на сервере и BigInt в вебе; результат каждой операции — не больше 10 знаков после запятой
   (округление `HALF_UP`, от нуля на середине) без хвостовых нулей, не больше 24 цифр до запятой (`number_too_large`);
   деление — до 10 знаков; деление на ноль — `division_by_zero`. Значение вычисляемого поля и умолчания по формуле
   округляется до `scale` поля.
5. **Пустые значения (семантика SQL):** операнд арифметики или сравнения `null` даёт `null`; `and/or/not` —
   трёхзначная логика с ранней остановкой (`false and x` = false, `true or x` = true без вычисления `x`); `&` читает
   `null` как пустой текст; `if` и `coalesce` вычисляют только возвращаемую ветку; `min/max` пропускают пустые,
   `len(null)` = 0, `contains` с пустым — false. Пустой текст поля — `null`, пустое поле да/нет — `false`. Условие
   (видимость, обязательность, только чтение) действует только при `true`; правило **нарушено только при `false`** —
   пустое значение правило пропускает, как CHECK в SQL.
6. **Границы:** текст формулы ≤ 1000 символов, ≤ 200 узлов, вложенность ≤ 20, аргументов функции ≤ 10, текстовый
   литерал ≤ 200 символов; значение-текст ≤ 4000 символов (`text_too_long`); даты — годы 1…9999 (`invalid_date`);
   счётчики дней, месяцев и знаков — целые (`invalid_argument`); не больше 10 000 вычисленных узлов (`budget`). Без
   циклов стоимость вычисления ограничена размером дерева.
7. **Ошибки.** Формула, которую нельзя принять, — 422 по адресу формулы (`fields[2].formula`, `rules[0].formula`), код
   `formula_<причина>` и ключ `error.formula.<причина>` с параметрами `position` (1-based позиция символа) и `name`;
   причины: `syntax`, `unknown_field`, `unknown_function`, `arity`, `type`, `argument`, `limit`, `self`, `cycle`,
   `result` (тип не подходит полю или условию). Формула, которая не может дать значение для этих данных, — 422 у поля
   или правила (`formula_division_by_zero` и др.), никогда не 500; стек вызовов клиенту не уходит.
8. **Где формулы стоят (simple-form формат 5, только живые формы):** у поля — `formula` (вычисляемое: только чтение,
   необязательное, без умолчаний и условий; типы text, textarea, number, date, datetime, time, bool), `defaultFormula`
   (умолчание новой записи; заменяет `defaultValue`), `visibleIf` (не может читать само поле), `requiredIf` (только у
   необязательного поля), `readonlyIf` (по записи **как она сохранена**, только для существующей записи); у формы —
   `rules` (1…20: ключ, условие, сообщение ru/uz/en до 200 символов, необязательное поле для показа). Формулы читают
   видимые поля формы; формулы скрытого поля хранятся, но не проверяются и не обслуживаются. Вычисляемые поля не могут
   ссылаться друг на друга по кругу (`cycle`). Всё проверяется при подготовке пакета, активации и новой версии.
9. **Сервер — источник истины.** Общий runtime (`EntityFieldValues`, `EntityLogicRun`) применяет логику на каждом пути
   записи — создание, изменение, массовое изменение и импорт (у живых форм импорта нет): вычисляемые поля никогда не берутся из тела,
   умолчания по формулам — для пустых полей новой записи в порядке объявления, затем вычисляемые поля (каждое после
   тех, что оно читает), скрытые поля очищаются, вычисляемые поля пересчитываются, затем `requiredIf` и проверки полей;
   правила — межполевые правила сущности (ADR-0032, 6.6), ответ `rule_failed` с ключом `error.studio.rule_failed` и
   параметрами `rule`, `message` (на языке запроса). Вычисленное значение хранится в `payload`, поэтому список, фильтры,
   отчёты, экспорт и вебхуки видят его без вычислений при чтении; записи, сохранённые до появления формулы, получают
   значение при следующем сохранении.
10. **Веб.** `form-meta` отдаёт каждому полю проверенные деревья его формул (`formula`, `defaultFormula`, `visibleIf`,
    `requiredIf`, `readonlyIf`), вычисляемому полю — `computed`/`readonly`, форме — `rules` с ключом словаря сообщения.
    Интерпретатор `core/formula` и `core/services/form-logic.ts` показывают значения и состояния, пока пользователь
    печатает, в том же порядке; правила проверяются до запроса. Редакторы Studio проверяют одну формулу через
    `POST /api/v1/studio/formulas/check` (право `studio.forms.publish`, ничего не хранит) и показывают причину и позицию.
11. **Часовой пояс запроса** — заголовок `X-Time-Zone` (регион базы часовых поясов; веб шлёт зону браузера, ту же, что
    использует превью), иначе UTC (`common.web.RequestZone`). Неверная зона — не ошибка: она сдвигает только «сегодня».
12. **Совместимость версий** — формулы действуют только при сохранении, чтение их не вычисляет; поэтому логика меняется
    свободно, кроме одного: поле с введёнными значениями не становится вычисляемым (`change_computed`), потому что
    следующее сохранение заменило бы данные. Точные правила — ADR-0041, «Этап 2, шаг 2.1».

## Последствия

- Администратор собирает документ с расчётами, умолчаниями, условиями и правилами без программиста; эталон — форма
  «Заказ (шапка)» (`e2e/tests/browser/instance/studio-order-formulas.spec.ts`).
- Одна грамматика и одна проверка на сервере; веб не парсит формулы. Любое изменение семантики меняет общий набор
  случаев, и падает тест той стороны, что отстала (`FormulaConformanceTest`, `formula-conformance.spec.ts`).
- Язык рассчитан на следующие шаги этапа 2: итоги строк документа (2.2) — та же арифметика над полями строки,
  условия статусов и согласования — те же условия, вычисляемые меры отчётов (2.3) — те же функции над агрегатами.
- Ограничения: нет функций над строками документа и агрегатов, нет ссылок на поля связанных записей, нет регулярных
  выражений и форматирования чисел; формулы есть только у живых форм (CLI доставляет формат 1).

Строки документа (2026-10-18, [ADR-0043](ADR-0043-live-form-documents.md)): ограничение «нет функций над строками
документа и агрегатов» снято — имена `lines.<таблица>.<колонка>` и `lines.<таблица>` читают строки, их принимают только
`sum` и `count` (сумма без строк — ноль); формула колонки читает строку и введённые поля шапки `doc.<поле>`. Общий набор
случаев дополнен; семантика остального языка не менялась.

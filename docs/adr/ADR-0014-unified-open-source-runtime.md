# ADR-0014: Единый open-source runtime SmartupCMS

**Статус:** Принято (2026-09-03)

**Заменяет:** ADR-0004 и ADR-0007 полностью; ADR-0001, ADR-0003,
ADR-0006, ADR-0008, ADR-0009, ADR-0010 и ADR-0011 — только в частях,
зависящих от Control Plane, fleet, лицензирования, Nomad, Consul или
обязательного Vault.

---

## 1. Контекст

SmartupCMS переходит от модели управляемого флота клиентских экземпляров к
самостоятельному open-source продукту. Поддерживаемая архитектура должна
соответствовать фактическим границам Maven, Angular и Docker Compose и не
создавать обязательной зависимости от центральной инфраструктуры Smartup.

## 2. Решение

1. Одна установка SmartupCMS обслуживает одну организацию и использует одну
   базу данных PostgreSQL. Изоляция разных организаций достигается отдельными
   установками, а не общей мультиарендной базой данных.
2. `apps/server` и `apps/web` — единственные application runtime продукта.
   Control Plane и отдельный runtime управления флотом в продукт не входят.
3. Поддерживаемая модель развёртывания — Docker Compose. Миграции выполняются
   отдельным одноразовым сервисом `migrate`; сервис `backup` является
   опциональным и запускается только при настроенной оператором конфигурации.
4. Продукт не содержит phone-home, удалённой регистрации установки, license
   gate, fleet registry или центрального привилегированного канала управления.
   Любая исходящая интеграция возникает только после явной настройки
   администратором установки.
5. В управляемой Smartup инфраструктуре edge размещается в Cloudflare, а
   объектное хранилище — в Cloudflare R2. Self-hosted оператор сам выбирает и
   контролирует провайдеров и может использовать любое совместимое
   S3-хранилище.
6. Multi-host HA и централизованная наблюдаемость не являются встроенными
   гарантиями поставки. Оператор может реализовать их своей инфраструктурой,
   но базовая поддерживаемая установка не зависит от них.

## 3. Последствия

- Установка остаётся работоспособной без связи с инфраструктурой Smartup.
- Обновления схемы отделены от старта приложения, а резервное копирование
  остаётся явно управляемой оператором возможностью.
- Возможности конкретного edge-, storage-, observability- или HA-провайдера не
  становятся обязательной частью переносимого runtime.

## 4. Трассируемость

История миграций и тексты заменённых ADR сохраняются без переписывания, чтобы
можно было восстановить причины прежних решений и переход к единому runtime.
Статусы исторических ADR явно указывают полную или частичную замену этим
решением.

# ADR-0021: Единая модель ошибок

**Статус:** Принято (2026-09-29)
**Дата:** 2026-09-29
**Зависит от:** ADR-0008 (базовая безопасность), ADR-0016 (поля и DSL запросов);
план 10/10, пункт 3.1

---

## 1. Контекст

Ошибки сервера шли тремя путями (подсчёт по коду на 2026-09-29):

| Путь | Как было |
|---|---|
| `ApiException` с кодом `ErrorCode` | 333 места; текст — литерал в коде, по-русски или по-английски |
| Иерархия `fnd` (`ConstraintViolationException` и наследники) | не обрабатывалась `GlobalExceptionHandler`: клиент получал 500 |
| Голые `IllegalArgumentException` / `IllegalStateException` | 149 мест; на пути запроса — тоже 500 |

Веб подменял текст сервера строкой каталога `error.<code>`, если она была, и
показывал текст сервера, если нет. Часть ответов шла как `application/json`,
часть — как `application/problem+json`.

## 2. Решение

1. **Одна база.** Ошибка, которой может закончиться запрос, — `ApiException`
   или её наследник. Исключения, которые запрос никогда не завершают (старт
   приложения, сбой поискового движка, перехваченный внутри), перечислены с
   причиной в `ErrorModelTest`; любое другое исключение приложения — ошибка
   сборки.
2. **Код, ключ, параметры.** Ошибка несёт `ErrorCode` (контракт для клиента),
   ключ текста в каталогах i18n и значения его `{плейсхолдеров}`:
   `ApiException.notFound(ErrorCode.I18N_LANGUAGE_NOT_FOUND, "error.md.language_not_found", Map.of("code", code))`.
   Код, который бросает ошибку, не пишет предложений. Ключи —
   `error.<модуль>.<имя>`; текст по умолчанию для кода — `error.<code>`.
3. **Текст рендерит сервер.** `GlobalExceptionHandler` (и обработчики
   security-цепочки, лимита запросов и идемпотентности) собирает
   `detail` на языке запроса: первый язык `Accept-Language`, если он активен;
   иначе язык системы (`system.default_language`); иначе русский. Строка,
   которой нет в языке, берётся из русского. Без базы данных используются
   каталоги из сборки; рендер ошибки сам не падает.
4. **Один формат.** Все 4xx и 5xx — RFC 9457, `application/problem+json`:
   `type`, `title`, `status` (совпадает со статусом ответа), `code`, `detail`,
   `instance`, `timestamp`, `errors` (поля) и новые `messageKey`, `params`.
   Непредвиденная ошибка отдаёт 500 `internal_error` без подробностей.
5. **Клиент.** Веб показывает текст по `messageKey` из своего каталога (язык
   мог смениться после запроса) и текст сервера, если ключа в каталоге нет.

## 3. Проверки

- `ErrorModelTest` — каждое исключение приложения наследует `ApiException` или
  внутреннее с причиной; обработчик отвечает на каждый подкласс.
- `ErrorTextsTest` — каждый текст, переданный `ApiException`, — ключ, и он есть
  в каталогах ru, en, uz. Исключений в тесте нет: литеральных текстов в
  вызовах не осталось (переход закончен 2026-09-29).
- `GlobalExceptionHandlerTest` — у каждого вида ошибки `application/problem+json`
  и свой код; `CatalogProblemMessagesTest` — выбор языка и отказоустойчивость.

## 4. Последствия

- Новая ошибка — это ключ и три строки в каталогах; переводчик правит текст в
  редакторе языков, не трогая код.
- Строка, переданная `ApiException` через переменную или константу, тестом не
  видна: такие места переводятся вручную и проверяются на ревью.
- Сообщения полей валидации Bean Validation (`errors[].message`) пока остаются
  текстом по умолчанию валидатора.

## 5. Уточнения (2026-10-01)

- Ошибка поля тоже несёт ключ: `FieldErrorItem.keyed(поле, код, ключ, параметры)`
  отдаёт `messageKey` и `params`, а `message` — текст на языке запроса, собранный
  так же, как `detail`. `ErrorTextsTest` падает на литеральном тексте в
  `new FieldErrorItem(...)` и проверяет, что каждый литерал `error.*` в коде есть в
  каталогах ru, en, uz.
- Предложение вместо ключа в `ApiException` наружу не уходит: обработчик пишет
  ошибку в журнал и отвечает текстом кода `error.<code>`.
- Вне Spring MVC формат тот же: 415, 406, отсутствующая часть multipart,
  заголовок или cookie — 4xx от `GlobalExceptionHandler`; отказ firewall
  Spring Security — 400 `error.request_rejected` (`ProblemDetailAuthHandlers`);
  исключение в фильтре и `sendError` контейнера — `ProblemErrorController`
  вместо ответа Spring Boot по умолчанию.

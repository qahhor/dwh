# ADR-0015: Перенос компонентов из общего UI-кита

**Статус:** Принято (2026-09-22), пересмотрено 2026-09-23
**Дата:** 2026-09-22
**Пересмотр 2026-09-23:** перенесённая копия — код продукта. Мы меняем её
свободно, если это делает продукт лучше; сходство с библиотекой целью не
является. Другие репозитории этим проектом не меняются (правило 2).
**Зависит от:** ADR-0002 (Angular), ADR-0012 (UI-фундамент), ADR-0014 (единый runtime)
**Изменяет:** ADR-0012 в части, касающейся переносимого подмножества

---

## 1. Контекст

В компании существует библиотека `@greenwhite/ui-kit` — Angular-компоненты
с Tailwind, которую использует фронтенд `kernel`. Мы изучили её исходники
(коммит `6472beb`) и сопровождающие руководства в `kernel` (коммит `b4775e8`).

Состав: 324 TypeScript-файла, 78 spec-файлов, 33 группы компонентов,
23 полевых контрола. Движок таблиц — около 5500 строк: основа `smt-table`,
серверная обёртка `smt-data-table` и локальная `smt-local-table` с
древовидным режимом.

Наш продукт закрывает тот же класс задач своими средствами: 20 рукописных
таблиц, 11 обёрток `shared/ui`, отсутствие выбора даты, единой обёртки поля
и диалога ошибки. Написать это заново — месяцы; взять готовое — вопрос
условий, изложенных ниже.

Существенные факты, установленные проверкой, а не предположением:

- Лицензия `@greenwhite/ui-kit` — **MIT** (`projects/core/package.json`).
  Она совместима с Apache-2.0 нашего репозитория. Файла `LICENSE` в
  репозитории библиотеки при этом нет: право заявлено только в метаданных
  пакета.
- Пакет публикуется в приватный реестр GitHub Packages и требует токена.
- Его зависимости включают `ckeditor5`, `codemirror`, `easymde`, `leaflet`,
  `html2pdf.js`, `ngx-image-cropper`. При нашем бюджете начального бандла
  в 500 kB и текущих ~399 kB установка пакета целиком невозможна.
- `peerDependencies` требуют Angular `^21.2.4`; у нас Angular 22.
- Тёмная тема в библиотеке **не реализована**: секция `[data-theme='dark']`
  в `tailwind.theme.css` закомментирована целиком.

## 2. Решение

**Переносим выборочное подмножество исходников под MIT-атрибуцией, а не
подключаем пакет зависимостью.** Перенесённый код живёт в
`apps/web/src/app/shared/ui-kit/` и собирается нашим Angular.

| Вариант | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| **Выборочный перенос исходников** | Берём только нужное — бюджет под контролем; компилируется нашим Angular; публичная сборка репозитория не требует токена | Копия расходится с библиотекой — это цель, а не издержка; сопровождение целиком на нас | **Да** |
| Подключение пакетом npm | Дёшево в момент подключения; обновления приходят сами | Тянет тяжёлые зависимости целиком; конфликт peer-версии Angular; приватный реестр ломает обещание self-hostable сборки под Apache-2.0 | Нет |
| Реализация только по спецификации | Нет заимствованного кода | 5500 строк движка таблиц и 78 наборов тестов уже написаны и проверены; переписывание — месяцы без выигрыша | Нет |
| Оставить как есть | Ноль затрат | 20 рукописных таблиц продолжают расходиться; для продукта о данных таблица — главный экран | Нет |

### Отношение к ADR-0012

ADR-0012 выбрал Angular Material + CDK и отклонил Tailwind как «ещё одну
парадигму стилей». Это решение остаётся в силе для всего существующего кода.
Настоящий ADR вводит одно ограниченное исключение: **внутри
`shared/ui-kit/` допускается Tailwind как build-time слой** перенесённых
компонентов. Смешивать парадигмы в одном компоненте запрещено.

Основание для исключения: правило ADR-0012 защищало команду от второй
системы стилей, написанной с нуля. Здесь вторая система уже написана,
протестирована и принадлежит компании; цена исключения — сборочный шаг,
а не новая парадигма для разработчика.

## 3. Правила (обязательные)

1. **Источник фиксируется.** Каждый перенесённый файл указывает путь и
   коммит-источник в заголовке. Текущая база — `smartup-ui-kit@6472beb`.
   Это нужно для атрибуции и как точка сравнения, если позже из библиотеки
   переносится что-то новое.
2. **Копия — наша.** Перенесённый код становится кодом продукта. Мы меняем
   его поведение, API и внешний вид всякий раз, когда это делает продукт
   лучше; быть похожими на библиотеку не требуется. Ошибки исправляются
   здесь. Репозитории `smartup-ui-kit`, `kernel` и `biruni` этим проектом
   не меняются: они — источники только для чтения. Существенное отличие
   от источника поясняется комментарием на месте правки, чтобы при
   следующем переносе было видно, что оставить своим.
3. **Атрибуция.** Каждый перенесённый файл сохраняет заголовок с MIT;
   `NOTICE` содержит запись о библиотеке. Файла `LICENSE` в репозитории
   библиотеки нет: лицензия заявлена полем `license` в
   `projects/core/package.json` на коммите-источнике, и это записано в
   `NOTICE`.
4. **Бюджет проверяется на каждой волне.** Перенос, выводящий начальный
   бандл за 500 kB, не принимается; тяжёлые компоненты грузятся лениво.
5. **Токены остаются нашими.** Перенесённый компонент читает семантические
   токены из `styles.css`, а не палитру библиотеки. Связь идёт через мост
   `@theme inline` в `tailwind.css`: каждая пара «роль утилиты + цвет»
   (`bg-`, `text-`, `border-`, `ring-`) отображается на токен. Гейт
   `npm run contrast:audit` падает на цвете, которого нет в мосте, на
   неинлайновом `@theme` и на паре фон/текст ниже AA в любой теме.
   Новый цвет из вновь перенесённого компонента добавляется в мост.
6. **Переносим поведение вместе с тестами.** Компонент без перенесённых или
   написанных заново тестов не принимается. Наше изменение перенесённого
   кода приходит со своим тестом.

## 4. Границы переноса

- **Берётся как есть** (не зависит от бэкенда): полевые контролы, `modal`,
  `drawer`, `alert`, `tooltip`, `menu`, `tab-bar`, `progress-stepper`,
  `pagination`, `badge`, `avatar`, `tags`, `dropzone`, `sortable-*`,
  основа `table`, сервисы темы, горячих клавиш и брейкпоинтов.
- **Берётся идея, пишется своё**: древовидный режим. `smt-local-table` в
  библиотеке помечен устаревшим и тянет модалки фильтров и настроек;
  вместо него — наш `smt-tree-table` на основе `table` (утилиты дерева
  взяты из библиотеки и переписаны на линейные проходы).
- **Требует адаптера**: `data-table` в серверном режиме, `data-select` и
  `multi-data-select`, `data-table-filter`. Все они обращаются к
  `QueryService`, построенному под контракт запросов Biruni
  (`p.column`, `p.sort`, `p.filter`, `d`). Нужен адаптер к нашему REST
  с keyset-пагинацией; базовый путь у библиотеки инъектируется через
  `provideSmtApiConfig`.
- **Не переносится**: `editor` (ckeditor5), `md-editor` (easymde — у нас
  свой), `content-maker` (liquidjs), `map` (leaflet), `charts`,
  `delivery-calendar`. `superset-embed` — только вместе с отдельным
  решением о row-level security: гостевой токен делегирует доступ во
  внешнюю систему, где наш `MdScopeService` не действует.

## 5. Последствия

- Таблица перестаёт писаться заново на каждом экране; 20 существующих
  реализаций сводятся к одной основе с двумя стратегиями данных.
- Сопровождение перенесённого кода целиком наше: сверки с библиотекой как
  обязанности нет, ошибки исправляются у нас. Главный риск — упустить
  полезное, что появится в библиотеке позже. Он закрывается правилом 1:
  новое переносится выборочно сравнением с коммитом-источником, наши
  изменения при этом не откатываются.
- Бюджет бандла становится ограничением каждой волны, а не разовой
  проверкой.
- Тёмную тему для перенесённых компонентов обеспечиваем мы: в библиотеке
  её нет.
